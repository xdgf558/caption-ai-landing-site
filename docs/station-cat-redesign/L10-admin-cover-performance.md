# L10 后台歌曲封面加载修复

生产后台用 64×64 的列表位置显示 1254×1254 原始 PNG，原素材接口为 `private, no-store`；切换作品还会重建整份列表。用户已授权修复并部署。本批仅处理这条图片路径，不修改发行平台配置或生产资料。

## 行为

- 歌曲列表改用 `/admin/api/music/site-content/assets/:id/thumbnail`，只交付已登记的 192 像素 card。每次 GET、HEAD 和条件请求都先通过现有 Access 管理员校验、内容后台开关、实际 schema 检查，再核对素材为 validated、未进入清理，以及当前 R2 对象身份。普通编辑管理员仍可查看待发布素材，不据此授予公开访问权限。
- 缓存为 `private, max-age=0, must-revalidate`，按 Cookie / Access 断言区分。304 同样经过管理员和对象检查。生成目录仍由 Worker 拦截，不能匿名直接访问。没有有效 card 或生成文件读取失败时返回错误并显示占位，列表不会回退下载完整原图。
- 作品列表按类型和 ID 保留节点。选择、资料刷新和分页不重新设置未变化图片的 src；封面变更只替换对应图片，旧请求迟到的失败事件不能覆盖新封面。点击事件读取最新的作品资料。
- 原素材查看继续使用既有管理员接口，保持 `private, no-store`。游戏截图、视频海报和公开音乐页的既有交付合同不变。

已有三张生产样本的原图总计 5,860,037 字节，对应当前 manifest 的卡片总计 19,424 字节；这是图片正文大小对比，不是页面耗时或 LCP 承诺。当前 11 首歌曲均有 card。后续没有生成卡片的新素材会显示占位，原图仍可查看；本批不引入请求内编码、自动生成任务、R2 写入或数据库迁移。

## 验证与部署边界

本机内容后台 70 项、公开查询及封面 49 项、旧音乐后台 28 项、staging 22 项通过。新增用真实临时 D1/R2 与签名 Access 夹具覆盖 card GET/HEAD/304、伪造和过期身份、无权限用户、关闭态、缺失 schema、非法查询、错误素材类型、缺少卡片、原素材查看、未验证素材及 R2 替换/删除；真实前端入口回归验证图片节点保留与封面切换。存储原件为合成身份夹具，不能代表生产素材授权。

首发构建未设置空正文选项，通过后仍为 60 个 HTML、426 个文件。托管 CI 按新提交另行核对。部署使用当前生产变量、绑定、Access、定时任务和旧内容关闭状态，只替换本批 Worker 与静态包；部署前后证据保存在本机私有发布目录，生产部署结果以实际版本与 HTTP / 已登录后台检查为准。

完整 CI 暴露了既有统计回滚夹具的分钟边界依赖：只在计数器 UPDATE 时注入故障，遇到新分钟 INSERT 会正常成功而导致错误断言。本批将测试故障注入放在 UPSERT 的 INSERT 入口，并显式删除临时 D1 的 global 计数器再核验新窗口回滚。33 项原生 D1/R2 运行时测试通过；不修改生产统计或事务逻辑。
