## 页面和路由

新增四语言游戏目录 `/{locale}/games/` 与作品介绍 `/{locale}/games/:slug/`，繁中规范地址省略语言前缀。《打工养猫日记》的介绍使用 `cat-life-game`，实际运行目录继续为 `/games/cat-life/`。`cat-life` 保留为运行名称，新处理器不接管该目录、无斜线形式或后代资源。游戏玩法、存档 schema 3、运行版本 1.28.0、账号和存档服务地址没有迁移。

页面复用已选“温柔小站”壳、五项导航和 T07 游戏公开 DTO，展示作品标题、简介、截图、设备及本机/云端说明。只有已登记的 `/games/cat-life/` launchPath 出现安全入口；其他作品不能借 slug 获得这个游戏的存档入口。截图为空时明确说明待补，不以插画冒充实机；支持设备取公开记录，不能据此宣布真机兼容已验收。本机截图为 T03 的 `cat-life-desktop.png` 原始字节，测试 D1/R2 权利记录不代表生产已配置素材审核。

仅当 `STATION_GAME_PAGES_ENABLED` 和 `STATION_CONTENT_PUBLIC_ENABLED` **同时开启**，处理器才在检查方法、参数或绑定前接管公开路径。未配置或只开任一开关返回 `null`，交回原 Worker/ASSETS 流程。两个开关同时开启但绑定/schema/资源不满足时返回受控失败；无映射作品详情返回 `null`。内部 Astro shell 始终不可直接公开访问。四语言规范化、HEAD、未知详情、运行资源和关闭态均有实际编译 Worker 回归。

HTML 保持 `private, no-store`、`noindex,nofollow`；本机 canonical 使用实际 loopback origin，公网 canonical 使用现有配置域名 `https://wwwstationcat.org`。本批未添加路由提案执行、sitemap 上线、AASA 扩围、生产绑定或远程迁移。请求截止只停止等待，不承诺取消已经发出的 D1 查询。

## 只读检测与真实运行衔接

介绍页和旧游戏共享 `saveStatus.js`，只读取存储，不归一化或写回。仅 `getItem() === null` 是缺失；空字符串、无效 JSON、根对象/必要字段不符、已知进度块损坏为损坏；不支持或未来 schema 为不兼容；存储 getter/getItem 异常为不可访问。兼容旧版本的归一化及重复猫 ID 修复仍由既有正常加载迁移处理，不在检测阶段写回。

| 只读状态 | 新介绍页 | 运行端行为 |
| --- | --- | --- |
| 游客缺失 | 开始游戏 | 显式点击后核对会话，在真正缺失槽位建立新游戏 |
| 已登录但本机缺失 | 进入游戏并核对云端 | 由既有云同步处理远端进度及冲突，不在介绍页判定云端为空 |
| 有效相容 | 继续游戏 | 重新核对实际会话和槽位后加载原进度 |
| 损坏/不兼容 | 查看恢复选项 | 显示保护面板；暂停玩法、自动写入及后续云衔接，保留原文 |
| 存储不可访问 | 查看恢复选项及重新核对 | 无法安全读取时不提供导入/导出，不创建进度 |
| 会话核对失败 | 状态说明及重试，没有启动 href | 不以缓存 ID 选择会员存档或写入 |

账号槽位来自新鲜的 `/api/readers/session`，使用现有会员键和游客归属规则。缓存账号标记只促使运行端核对身份，不作为授权。会员槽位缺失时，只有有效且尚未归属其他账号的游客进度可以进入既有游客接续；已有会员 A 的状态不能复制到会员 B。新入口只带 `sc_entry=1` 和合法语言，不把账号、原始存档、token 或云端数据放入地址/公开 DTO。

运行端的 `loadGame()` 仅对真正缺失返回 `null`。损坏、不可读和不支持版本抛出保护状态，`loadOrCreateGame()` 因而不再静默覆盖异常。停止自动创建 `:compat-v3` 新进度；历史兼容副槽位不删除，也不会自动切换过去。直接旧地址中的正常游客离线进度保留原启动路径，带新入口标记、缓存会员或异常游客数据时必须先核对会话。

`saveSystem` 在正常保存、自动保存、重置、账号切槽及云端应用前读取当前原文，与已观察的原文比较。检测到异常、外部编辑或 get/set 失败时发出只含状态的保护事件，主循环/交互停止，游戏自身 BGM 暂停，云客户端撤销排队计时器并忽略后续应用/上传。云端读取完成后及每次 PUT/POST 前重新核对会话，身份变化时停止衔接。现有权限、云端冲突协议和规范化后 **750000 字节**限制不改。

## 明确恢复

保护面板提供重新核对、可读取原文时的原始导出、以及相容本机 JSON 文件恢复。文件选择后再次核对会话和槽位，用户确认后才调用导入；旧槽位原始字符串先存到唯一 `:recovery:<时间>:<随机值>` 副本，并验证字节一致、目标未变，再替换经过既有归一化的相容文件。备份失败或目标在已观察之后改变时拒绝替换；失败可能留下已生成的原文副本。没有自动重置、自动云恢复或主动删除异常数据。

本机原文检测和文件选择限额为 32 MiB（字符串检测按字符长度，文件按字节）；这不是云存档限额。保护状态下的导入不执行云端写入，重新载入后仍由原有云同步核对。正常运行内用户明确导入或重置继续走既有同步衔接，不重写服务权限。

localStorage 的读取、比较与 setItem 不是跨渲染进程原子 CAS，仍存在最后一次比较之后的极小竞争窗口；已经发出的云请求不能被这批逻辑取消或回滚。身份重新核对也不把 Cookie 切换与服务端写入变成原子操作。保留这些边界，不声称具备任意并发恢复保证。
