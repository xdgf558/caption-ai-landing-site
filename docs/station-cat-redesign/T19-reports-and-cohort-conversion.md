# T19 聚合与运营报表

T19 在既有音乐后台增加 `/admin/music/reports/`，从 T18 已接收事件计算推广报表，并独立登记平台提供的曝光和播放数据。它不把外链点击改名为平台播放，不重新定义音乐权益，也不替用户确定主推作品。基线为已合并 T18 的 `cd1ea33964f47c2e3806f81c8b01a12f772caf4e`，本任务分支为 `codex/station-cat-redesign-t19`。

## 查询与转化口径

时间采用服务端 `received_at`；日期输入表示 UTC 半开区间 `[from, to)`，结束日期不含当日。每次最多查询 31 天，起点限于最近 12 个日历月。当日可以读取截至服务端当前时刻的部分数据，页面明确标注时间；当日未结束的范围不能保存为精确快照。

| 指标 | 口径 |
| --- | --- |
| 单曲访问、试听开始、有效试听、平台点击 | 分别累计已成功采集的对应事件次数；重复操作可以增加次数 |
| 有效试听 | 沿用 T18：前台实际播放累计至少 10 秒，或原生自然 `ended`；不混入旧音乐的 30 秒/50% 和 90% 字典 |
| 试听转化率 | 已关联试听开始的 `(session_id, track_id)` 去重数 / 所选访问记录的同一组合去重数 |
| 平台点击转化率 | 已关联平台点击的 `(session_id, track_id)` 去重数 / 所选访问记录的同一组合去重数 |
| 短片开始、短片结束 | 成功采集的站内原生播放和自然结束次数 |
| 游戏请求、游戏就绪、本机保存 | 分别为请求、运行端就绪回报、本机写入后回读成功；没有就绪回报时显示“暂无数据” |
| 完整音频开始 | 既有权限链成功准备并开始播放的事件；不授予新权益 |

事件与访问必须在同一筛选结果、同一歌曲、同一会话和同一时间窗中，访问先于或等于事件，间隔小于 30 分钟。后来的访问、恰好早 30 分钟的访问、另一首歌或窗外访问都不能补分母。存在未关联的试听/点击时，该指标仍显示独立总次数、已关联分子、访问分母及未关联次数，但转化率为空。分母为空时也不计算百分比。这里的会话组合不是唯一访客、账号身份或跨设备身份。

筛选支持歌曲、渠道、Campaign、素材/Clip 和平台。渠道使用明确命名空间：`campaign:<登记 source>`、`direct_or_unknown`、`unknown`，避免与名为 unknown 的真实渠道混淆。归因来自 T18 接收时冻结的字段，历史读取不要求 Campaign 或作品当前仍发布。素材采用事件自身 Clip，缺失时使用 Campaign 登记 Clip。平台筛选仅约束平台点击，访问与试听分母仍保留同一歌曲/渠道/Campaign/素材群组。

## 固定样本与复算

以下均为隔离夹具，不代表真实歌曲或发行数据。

| 同一天的歌曲 A 会话 | 访问次数 | 试听开始 | 有效试听 | 平台点击 |
| --- | ---: | ---: | ---: | ---: |
| S1 | 2 | 2 | 2 | 网易云 4 |
| S2 | 1 | 1 | 1 | Apple Music 1 |
| S3 | 1 | 0 | 0 | 0 |
| 合计 | 4 | 3 | 3 | 5 |

访问分母为 3，试听及点击转化分子均为 2，结果为 `2/3 = 66.7%`。单选网易云仍有 3 个访问会话，4 次点击只形成 1 个转化会话，结果为 `1/3 = 33.3%`。歌曲 B 的同名会话不会混入 A 的分母；unknown 下两个没有所选窗口访问的点击保留次数，转化率为空。

跨日样本再加入前一天 S1 对歌曲 A 的访问：整段时间是 5 次访问、3 个去重组合，每日组合相加却是 `1 + 3 = 4`。历史报表因此只相加事件次数，不把每日会话数当作整段去重分母；精确保存该时间窗后，仍能恢复原来的 3 和 66.7%。[可复算记录](evidence/T19/arithmetic.json) 由 `node scripts/rehearse-station-reports.mjs` 生成，随机 ID 和当前日期会变化，算术结果固定。它直接构造接收回执形状，T18 真实采集去重另有专项测试。

## 原始数据、历史聚合与缺失值

近期查询保守使用最近 89 个 UTC 日期，避开 T18 的 90 天原始事件删除边界及其清理宽限。SQL 对同一时间窗精确去重，不向管理员返回会话 ID、事件 ID、原始 IP、账号信息、音频地址或认证信息。每次最多处理 20,000 个筛选后事件，超限返回明确错误，不截断成成功报表。

0017 追加六张 STRICT 表：`station_report_snapshots`、`station_report_jobs`、`station_report_health`、`station_report_retention_guard`、`station_external_metrics`、`station_report_operations`。快照只保存 17 个白名单非负整数和查询维度，不保存访客标识；已经生成的快照不可更新。每日任务在实际出现的维度交集及其“不限定”父维度上建快照，同时覆盖五个平台。单日最多 512 个查询键，每次 cron 最多处理 16 个，游标与快照在同一 D1 批次推进。

原有 cron 为每小时一次：即便没有故障，384 个键/天的理论吞吐也不能保证持续覆盖每天 512 个键的上限。T20 启用前必须结合实际维度规模、套餐和原有 cron 工作量核对覆盖进度；积压、超限或原始来源过期会停在原游标，不跳过并宣称完成。本批没有生产补算、调高 cron 频率或承诺历史覆盖完整。

超过近期范围时优先读取同一查询键、同一完整时间窗的精确快照。否则只有每一天都已完成聚合才累计事件总次数；跨日去重会话和百分比保持空。单日可以显示该日自己的分母/转化。已完成日期内从未出现的交集是已知零值，尚未完成日期是“暂无数据”。“保留此时间窗的精确聚合”仅对已结束的近期范围可用，保留当时的精确分母和结果；不会用每日相加伪造它。

聚合快照、每日任务和人工平台数据在时间窗结束后的 12 个日历月到期，闰年日期按日历规则收敛。独立受控清理仅处理上述表和短期操作回执，每表每次最多删除 1,000 条到期记录。健康检查要求最近两小时内成功清理且没有到期积压；否则停止新登记、快照写入和聚合。关闭查询或聚合开关不会关闭已经明确启用的到期清理。它不执行读者销户，不改 T18 的原始事件清理或旧音乐留存规则。

## 平台曝光与播放登记

发布者必须明确选择所属歌曲、指标、平台、统计时间窗、数据截至时间、来源类型和来源说明，并确认使用平台认可的数据。来源类型限平台后台或平台导出；说明不接受 URL、控制字符或 HTML。数值为非负整数，只有明确来源的零值才显示 0。未登记保持“暂无数据”，站内点击不会自动生成或推算平台播放量。

每条人工记录独立展示，不自动相加重叠时间窗，也不计算曝光/播放的外部转化率。只有显式筛选歌曲和平台，并且统计时间窗、Clip、Campaign、渠道范围相符时才标注范围相符；这仍需独立核对来源真实性。较宽或不同范围的记录可供参照，但会标注无法计算精确转化率。撤回记录保留撤回状态。修订固定作品、指标、平台、时间窗和关联资料，使用 `If-Match` 版本 CAS；改归属需撤回原记录并新建。

筛选资料每种最多 200 项，相关人工记录最多 100 条，超限明确返回预算错误。当前没有分页、CSV 文件上传或平台 API 同步；“人工导入”通过带来源的登记表单实现。真实平台数据、素材权利与两周运营基线仍需运营提供，本批没有填写或承诺增长结果。

## 鉴权、开关和恢复

API 位于 `/admin/api/music/site-content/reports`。沿用实际验证的 Cloudflare Access JWT 和原后台角色，GET/HEAD 是私有 `no-store`，所有写入要求同源 CSRF 检查及发布者身份；编辑者只读。报表页 `noindex,nofollow,noarchive`，正式用户导航不改。读取历史报表不要求 R2 或公开音乐页面开关。

服务要求独立 MUSIC_DB、实际 0016/0017 账本及所有查询依赖表列，不根据迁移文件存在自动建表。需要原 `STATION_CONTENT_ADMIN_ENABLED`、`STATION_REPORTS_ENABLED=true` 和 `STATION_REPORT_POLICY_VERSION=station-reports-v1`。定时聚合另需 `STATION_REPORT_AGGREGATION_ENABLED=true`；写入/聚合还需 `STATION_REPORT_RETENTION_ENABLED=true` 及清理健康。新开关没有加入生产启用值，0017 只在临时本机 SQLite/D1 执行。

报表有独立的本机恢复键 `station-reports-admin:v1:<actor>`，与旧内容发布日志互相拒绝跨范围重放。操作先保存原命令、版本和幂等键；丢回执、刷新或身份变化不生成新操作。服务端操作回执只保留最小结果约一天，旧永久 mutation 日志和审计不写统计值或来源说明。

幂等键携带首次操作时间，服务端要求不晚于当前时间五分钟、且未超过 24 小时；回执到期与该键一致。即使到期回执已清理，原键也返回 `REPORT_OPERATION_EXPIRED`，不会再次插入。过期 pending 保持阻止后续写入，需人工核对登记结果后受控恢复本机日志；本批没有自动丢弃或重建按钮。客户端 30 秒超时只停止等待，不撤销已发 D1 请求；D1 批次解决本库 CAS 和回执原子性，不构成 D1/R2/Access 跨系统回滚。

账号销户清单为六张表补只读分类，`approved=false`、`executionEnabled=false` 保持不变。原 64 张读者表、27 张旧音乐表及既有分类不因本任务被授权删除。
