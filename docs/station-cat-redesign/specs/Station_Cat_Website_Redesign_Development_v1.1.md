# Station Cat 音乐与游戏网站改版开发文档

版本 v1.1
编制日期 2026年10月5日
适用对象 产品设计 前端 后端 测试与 Codex 开发代理
性质 产品需求与实施基线 具体接入方案以仓库检查结果为准

本次改版以 Station Cat 个人品牌推广为主要目标，公开内容集中到音乐和游戏。大部分歌曲在各大音乐平台发行，网站负责官方作品展示、推广内容与平台收听入口；站内试听按后台推广歌曲模块的配置提供。游戏部分提供作品介绍、开始游戏和继续游戏。保留现有站内播放器与账号能力，迁移时保护订单、余额、已购权益与游戏存档。本期优先完成品牌展示、推广配置和核心使用路径，收费体系调整单独立项。

本文可以用于拆分开发任务、约束实现和验收。它没有依据仓库代码确认当前技术栈、接口、数据库或部署方式，因此所有建议接口与字段均为逻辑契约，开发者需要映射到现有系统后实施。本文不授权删除生产数据或变更现有用户的付费权益。

## 1 项目依据与设计边界

### 1.1 已确定的信息

用户明确要求改版网站主要用于推广个人品牌，公开内容围绕音乐和游戏展开，其他旧公开栏目与入口在新版开发完成并上线后关闭。大部分歌曲在各大音乐平台发行，重点接入网易云音乐、汽水音乐，后续增加 Apple Music，并通过音乐短视频推广。Station Cat 网站承担官方作品与品牌展示、推广内容和跨平台收听入口的职责，站内试听由后台专门模块逐曲配置。

实际域名使用 https://wwwstationcat.org/。前期讨论中的 stationcat.org 只作为举例出现，本文不要求换域名。音乐频道沿用 /music/ 作为规划基础，游戏的新地址需要经过旧路由清单核实。

## 2 产品目标与本期范围

### 2.1 核心目标

访客从推广链接直接进入对应歌曲页，了解个人品牌与作品，并按后台配置找到已上线的平台链接；开启公开试听的推广歌曲提供免登录试听，未开启时以作品内容与平台收听入口为主。游戏访客能看懂玩法并开始游戏；有有效存档时能继续游戏。运营者在既有后台的专门模块配置推广歌曲、站内试听、平台入口与推广素材，并区分网站访问、媒体实际开始播放和外站点击。

| 优先级 | 功能范围 | 完成条件 |
| --- | --- | --- |

| P0 | 音频与短视频互斥 外链状态管理 | 无重复出声 无假发行入口 |
| P0 | 内容后台 推广歌曲配置 归因统计 旧地址迁移 | 无需改代码即可日常运营 可回退 |
| P0 | 手机适配 无障碍 基础 SEO | 真机与键盘路径通过验收 |
| P1 | 歌词搜索 歌单 扩展数据报表 | 根据内容规模与首期数据安排 |

| 后续 | 收藏云同步 音乐独立订阅 iOS 权益互通 | 另行补充账号与权限规格 |

本期不增加社区、创作者入驻、排行榜交易体系，也不重写游戏核心玩法。小说、文章、通用工具、其他 Apps 的公开介绍及被新版替代的旧公开入口，在新版开发完成并上线后直接关闭，开发期间不提前关闭。依赖本站的授权接口、支持页、支付回调、账号和存档服务需先盘点，接入新版并保持有效；关闭旧公开入口不等于删除历史业务数据。

## 3 信息架构与地址规划

### 3.1 页面与路由

以下为不带语言前缀的逻辑路径。若仓库已有 /en/、/zh-hant/ 等规则，保持规则一致，并提供对应 canonical 与 hreflang。开发前确定唯一的 URL 生成函数，避免页面、二维码、分享链接分别拼接地址。

| 页面 | 逻辑路径 | 职责 |
| --- | --- | --- |
| 首页 | / | 品牌说明 当期主推音乐 游戏入口 |
| 音乐目录 | /music/ | 发现 搜索与进入单曲页 |
| 单曲官方页 | /music/tracks/:slug/ | 试听 平台选择 短视频 MV 歌词 |
| 游戏目录 | /games/ | 展示实际可玩的游戏 |
| 游戏介绍 | /games/:slug/ | 玩法 截图 支持设备 开始与继续 |
| 游戏运行页 | 保留现有运行地址 | 游玩 存档 设置 返回 |
| 我的 | /account/ 或既有地址 | 账号 已有权益 订单 存档与收藏入口 |
| 服务页面 | 既有支持 隐私 条款地址 | 保留有效服务与政策 |
| 管理后台 | 既有管理前缀 | 内容 发布 推广与报表 |

不新增独立音乐子域名。歌曲 ID 稳定且不可复用；slug 修改后，旧 slug 永久重定向到新地址。游戏运行 URL 尽量保持稳定，避免影响缓存、安装入口或现有存档作用域。

### 3.2 导航规则

桌面顶部为品牌标志、音乐、游戏、语言菜单和我的。品牌标志返回首页。手机使用首页、音乐、游戏、我的四个底部入口，语言设置收进我的或顶部菜单。当前页面有可见选中状态。

点击音乐后使用持久的站内播放器；进入游戏运行页隐藏网站导航与迷你播放器。退出游戏后恢复网站布局，并保持音乐暂停，用户主动决定是否继续播放。

## 4 页面功能规格

### 4.1 首页

顺序为品牌首屏、主推歌曲、音乐短视频、主推游戏和页脚。首屏文案建议为“听一首歌，玩一会儿”，配“听音乐”和“玩游戏”两个按钮。插画控制高度，手机首屏能看到两个入口。首次访问不自动播放音视频。

主推歌曲从后台推广歌曲模块选择，展示封面、标题、艺名、简短介绍与详情入口；仅在该模块开启且资源有效时显示试听按钮。最多附带三首精选歌曲。平台按钮使用后台配置并核验的已上线链接，作为主要收听入口。音乐短视频展示最多四张封面卡片，点开播放器；没有已发布素材时隐藏整个区块。

游戏区优先展示《打工养猫日记》或运营后台选定的实际作品，使用真实截图。仅有一款游戏时突出这一款。页脚保留支持、隐私政策、服务条款与版权信息，不增加旧内容目录。

### 4.2 音乐目录

展示主推歌曲、精选作品和曲目列表。每条记录包含封面、标题、艺名、可用时长与详情入口；试听或播放按钮按后台配置和实际音频模式显示。点击标题进入单曲页，已上线平台为主要收听入口。P0 搜索标题与艺名，默认按后台排序，提供最新发行排序。分页或游标加载，禁止首屏拉取全站媒体文件。

筛选后无结果时提供清除条件操作。加载失败提供重试。若曲库不足以形成歌单，不显示空歌单区域。试听和详情访问不要求账号。

### 4.3 单曲官方页

手机首屏附近显示封面、歌名、艺名、可用时的播放或试听按钮，以及“选择收听平台”。随后排列短视频、MV、歌词、创作介绍和最多三首相关歌曲。平台数量多时使用紧凑按钮组，避免大面积重复卡片。

歌曲在音乐平台发行与网站作品页公开是两种独立状态，网站公开作品页不代表提供站内完整播放。音频沿用无站内音频、试听、免费完整播放或现有权限完整播放四种模式；推广模块单独控制公开试听是否开启及其资源。开启且资源有效时，游客可免登录试听并看到明确时长；未开启时不承诺免登录试听。完整播放仍按实际模式与现有权限执行，不因推广配置自动变为免费。无可用站内音频时保留真实外站入口，不渲染空播放器。

后台开启推广试听时，必须配置独立剪辑且可公开访问的试听文件，发布配置前检查资源就绪与使用权限。仅靠前端在指定秒数暂停完整音频，无法限制下载或绕过播放。付费完整资源继续使用服务端权限校验和既有访问凭证，不将完整资源 URL 写入公开接口。

未发行的平台显示“即将上线”文本或隐藏，不提供虚构链接。地区不支持时显示对应提示并保留其他已上线选项。已下架平台不继续引导点击。全曲都未发行时，页面以站内音频和内容展示为主。

评分与收藏沿用真实现有能力。游客本机收藏明确标为“保存在此设备”；缺少云同步时，不显示“已同步”。本期不因新增入口改变收藏存储协议。

### 4.4 音乐短视频与 MV

短视频是歌曲下的内容资产，P0 在首页和单曲页展示，不建立单独的视频社交频道。每条素材必须关联一首主歌曲，记录时长、封面、素材类型、版本号、字幕、发布日期及平台发布记录。

视频采用用户点击播放、移动端 inline 播放、封面预览及按需加载。播放时暂停站内音频和其他视频；关闭弹层或切换素材立即暂停并释放活动状态。结束后显示歌曲入口与已上线平台按钮。

MV 作为独立关联素材管理。外部嵌入受阻时显示原平台链接；自托管失败显示重试。网站地址无法证明短视频在哪个平台真正发布，运营者需要保存真实发布链接和发布 ID。

### 4.5 游戏页面与运行页面

介绍页包含真实截图、玩法摘要、设备支持、游客存档说明及主要操作。启动按钮与加载状态区分。只有检测到有效且兼容的存档才显示“继续游戏”；损坏或版本不兼容时提供恢复路径，不静默覆盖。

游客首次进入按现有能力直接游玩。云存档或已购装扮需要账号时，在对应操作处提示登录。介绍页不得承诺未经核实的设备或同步能力。

游戏运行页保持沉浸，保留返回、设置与存档功能。启动前暂停网站媒体；加载失败恢复站点导航且提供重试，音乐保持暂停。游戏音频继续由游戏控制。游戏原声链接可放入暂停菜单，本期不添加强制音乐推广弹窗。

### 4.6 我的与服务页面

我的页面提供账号、现有订阅、订单、余额、已购权益、游戏存档与现有收藏入口。内容栏目下线后，历史购买记录和售后仍可访问。音乐独立会员价格、权益、账号删除与 iOS 互通不在本次页面改版中重新定义。

## 5 视觉与交互规范

前端设计开发时必须直接调用已安装的 Product Design UI 设计技能：先使用 product-design:index 与 product-design:ideate 生成 3 个具有明显差异的可视化模板方案，以首页和个人品牌展示为主要设计对象，说明手机适配思路，交由用户选择。用户选定后再进入前端视觉编码，并按所选方案实现；用户未选择前可继续仓库盘点、数据模型等无依赖工作。

深蓝灰背景、米白文字和少量暖金强调作为初始设计参考，最终视觉体系以用户选定模板为准。猫咪与车站作为品牌元素，主要视觉内容由歌曲封面和真实游戏画面承担。禁止首页自动轮播、重复推广横幅和多个浮动控件叠加。

| 项目 | 建议值或规则 |
| --- | --- |
| 页面背景 | #10151F |
| 卡片背景 | #192130 |
| 正文颜色 | #F4F1EA |
| 次要文字 | #B7BFCC |
| 强调色 | #E6B86A |
| 桌面内容宽度 | 最大 1120px 两侧保留留白 |
| 手机横向边距 | 16px 起 |
| 间距 | 8 12 16 24 32 48px |
| 卡片圆角 | 12 至 16px |
| 正文字号 | 16px 起 随语言与设备适配 |
| 触控目标 | 建议至少 44 × 44px |

上述数值是初始设计建议，可按用户选定模板调整，颜色组合必须实际检查对比度。交互具有键盘焦点和可读名称，状态不只依靠颜色。弹层打开后焦点进入弹层，关闭后回到触发元素；支持 Escape。遵循减少动态效果设置。

布局验收至少覆盖 375、390、768、1280、1440px。屏幕窄时曲目行保留标题与播放操作，其他信息折行或收起。迷你播放器只在已选中曲目后出现，底部导航、播放器和安全区域的高度统一计算；正文底部 padding 足够，按钮和歌词不被遮挡。

## 6 媒体播放与权限规则

### 6.1 统一播放协调

站内只允许一个活动音频来源。统一协调器管理网站音频、短视频与 MV，并记录当前媒体 ID、来源、状态和播放会话 ID。页面切换不重复创建网站 audio 实例。快速切歌时使用请求版本或取消机制，旧请求不得回写新曲目的状态。

播放状态包括 idle、loading、playing、paused、ended、error。调用 play() 后等待实际成功再更新状态，使用 playing 事件确认开始并上报。自动播放被浏览器阻止时保留播放按钮，显示可重试提示。[1]

| 用户操作 | 协调器行为 |
| --- | --- |
| 播放歌曲 B | 暂停歌曲 A 取消过期加载 切换媒体 |
| 播放短视频 | 暂停网站音频与其他视频 |
| 关闭视频 | 暂停视频 音乐继续保持暂停 |
| 进入游戏 | 暂停所有网站媒体 隐藏播放器 |
| 游戏加载失败或退出 | 恢复站点界面 保持音乐暂停 |
| 切换歌曲详情页面 | 当前站内播放可持续 不自动切到新歌 |
| 刷新或首次打开页面 | 可恢复曲目选择 不自动出声 |

跨域 iframe 无法默认受同一协调器完整控制。P0 只展示 Apple Music 外链；可选嵌入在专项验证后启用。无法验证暂停控制时，进入游戏应卸载 iframe；同页出现不可控有声嵌入时，不允许同时启动站内音频。

### 6.2 Apple Music 的接入边界

Apple 官方提供链接、徽章与用于预览的嵌入播放器。[2] 本期不承诺登录后完整播放，也不将其作为站内权限系统的一部分。正式开启嵌入前需要验证订阅、地区、浏览器、登录状态、加载失败和音频协调。未通过时保持链接按钮。

### 6.3 文件与访问控制

封面和公开试听可以缓存；付费完整音频的读取必须由服务端校验。复用当前对象存储与 CDN，管理端上传后进行格式、时长、尺寸、大小和完整性校验。视频先显示封面，用户点击后加载播放文件。上传不直接覆盖线上文件，使用版本化资源键。

保留已有完整音频权限，不以改版为由降级老用户权益。歌曲权利与试听、短视频、MV 的使用范围由运营者逐曲登记；未确认允许发布的资源保持草稿。本文不替代发行协议或授权核查。

| ClipPublication | clip_id channel post_id post_url published_at | 支持同素材多平台发布 |
| Game | id slug title description screenshots launch_url status supported_devices | 运行地址使用可信范围 |
| HomeConfig | featured_track_id selected_clip_ids featured_game_id revision | 只引用已发布对象 推广歌曲取自专门配置模块 |
| PromotionTrackConfig | track_id enabled preview_enabled preview_asset_id selected_platform_link_ids selected_clip_ids sort_order revision | 引用公开歌曲 开启试听要求独立公开资源就绪 平台链接须核验 |
| Campaign | id source medium track_id clip_id landing_path status | ID 唯一 归因按已登记值解析 |
| AnalyticsEvent | event_id event_name timestamp track_id clip_id game_id campaign_id session_id | event_id 去重 不含私有媒体 URL |
| RouteMigration | old_path action new_path reason approved_at | action 为 keep redirect retire service |
| PublishAudit | actor object_id revision action timestamp | 内容变更可追溯 可恢复 |

Track.status 为 draft、scheduled、published、archived。歌曲公开发布时间与外部平台发行时间分别记录。PlatformLink.status 为 planned、live、unavailable、removed，只有 live 且 URL 已核验的记录渲染可点击入口。具体 provider 使用 netease、qishui、apple_music，后续平台通过配置扩展。

site_audio_mode 为 none、preview、free_full、existing_entitlement。现有会员校验映射到 existing_entitlement，不在公共 Track 中暴露可直取的完整资源。PromotionTrackConfig 管理推广资格与独立公开试听；preview_enabled 不改变完整资源的会员权限。Track 的公开状态表示网站作品页是否可访问，PlatformLink 表示外部发行状态，二者分别管理。Clip 发布独立于歌曲平台发行，已发布 Clip 只能指向公开可访问的歌曲页。

所有日期以 UTC 存储，后台显示明确时区。发布操作原子化地校验引用与资源状态，再切换公开版本；审核失败返回具体字段错误。归档歌曲仍为历史订单保留内部 ID，公共页下线方式按迁移清单决定。

## 8 接口契约

接口前缀沿用仓库约定，下表给出资源与行为。不得新增一套平行账号 API。

| 方法与逻辑资源 | 行为 | 权限 |
| --- | --- | --- |
| GET /api/music/tracks | 搜索 排序 游标与 limit 返回公开摘要 | 公开 |
| GET /api/music/tracks/:slug | 返回发布详情 平台状态与媒体公开字段 | 公开 |
| GET /api/music/tracks/:id/playback | 按推广试听配置及音频模式返回公开试听或完整资源权限校验结果 | 按资源规则 |
| GET /api/music/tracks/:id/clips | 返回已发布短视频与 MV | 公开 |
| GET /api/games | 返回公开作品列表 | 公开 |
| POST /api/analytics/events | 接受有限事件批次 | 公开 限流 |
| POST /api/admin/media/uploads | 发起受控上传 | 管理员 |
| POST /api/admin/tracks/:id/publish | 校验 发布并记录版本 | 管理员 |
| PATCH /api/admin/platform-links/:id | 修改状态 地区与链接 | 管理员 |
| POST /api/admin/campaigns | 创建推广来源记录 | 管理员 |

列表默认 limit 20、上限 50，排序稳定并含 ID 作为并列条件。公开不存在或未发布歌曲统一 404，避免暴露草稿。受保护播放返回明确的 401、403、429 或 503，网络故障不误报为会员到期。所有错误使用 { code, message, request_id }，不返回堆栈或私密凭证。

PATCH 与发布接口带内容 revision；并发修改返回 409，提醒重新载入。管理动作沿用现有鉴权与 CSRF 防护。发布、媒体上传确认等可重试操作具有幂等标识，重试不得产生重复资产或重复公开版本。

外链使用后台已核验的 HTTPS URL。优先渲染普通链接，不等待统计请求再跳转。若提供站内跳转资源，只能通过 platform_link_id 查找后台记录，禁止传入任意 target URL。外部链接配置 noopener，查询参数不拼接到发行平台 URL。

## 9 推广链接与数据口径

### 9.1 链接格式

单曲长期地址保持稳定，例如 https://wwwstationcat.org/music/tracks/today-isnt-over/。slug 仅为示例，生产标题与平台链接从实际曲库录入。

推广链接使用标准参数，例如 ?utm_source=douyin&utm_medium=short_video&utm_campaign=release_2026_10&utm_content=clip_001。同一素材在不同渠道创建独立 Campaign。二维码使用同样的落地地址和归因参数。页面 canonical 去掉归因参数。

旧 src 参数如已有推广使用，支持映射为已登记 Campaign。未知或长度过大的值不进入报表维度，归为 unknown。缺少参数与 referrer 时归为 direct_or_unknown，不猜测渠道。

推广源优先取本次落地页合法 Campaign；同一会话保留首次合法来源，新的有效 Campaign 开启新归因上下文。会话建议在 30 分钟无活动后结束，时间阈值可以后台配置。P0 不做跨设备身份追踪或长期广告画像。

### 9.2 事件定义

| 事件 | 触发条件 | 去重规则 |
| --- | --- | --- |
| track_view | 单曲内容加载成功且可见 | 同会话同歌曲 30 分钟一次 |
| preview_start | 试听文件实际 playing | 同 playback_id 一次 |
| full_audio_start | 获准完整文件实际 playing | 同 playback_id 一次 |
| preview_qualified | 前台实际累计试听至少 10 秒或试听结束 | 同 playback_id 一次 |
| platform_click | 用户激活已上线平台链接 | 同 interaction_id 一次 |
| clip_start | 短视频实际 playing | 同 playback_id 一次 |
| clip_complete | 媒体实际 ended 且未跳过主要内容 | 同 playback_id 一次 |
| game_launch_request | 用户点击启动或继续 | 同 launch_id 一次 |
| game_ready | 游戏运行端完成加载并发出就绪 | 同 launch_id 一次 |
| save_success | 实际存储操作确认成功 | 同 save_operation_id 一次 |

播放时间累计排除暂停、等待、拖动跳跃和隐藏页面时间。platform_click 表示点击意图，无法证明外部 App 已打开或歌曲实际播放。即使游戏 iframe load 成功，也不能直接产生 game_ready。

游戏运行端通过已有桥接或 postMessage 上报就绪，接收端校验 origin、source、game_id 和 launch_id。没有运行端确认能力时，报表仅显示启动请求，game_ready 标为暂无数据。

### 9.3 报表与指标

P0 展示按歌曲、渠道、Campaign、Clip 和平台的访问、试听开始、有效试听、平台点击与游戏就绪。平台点击率使用“发生平台点击的单曲访问会话数 / 单曲访问会话数”，避免重复点击让比例超过 100%。试听开始率采用同样的会话口径。总点击次数另列。

短视频曝光量来自对应平台，首期允许人工录入并标注来源、统计时间窗和更新时间。外部曝光与站内访问的时间窗或归因不一致时，不展示精确转化率。网易云、汽水、Apple Music 的平台播放量只能来自平台认可的数据，和站内事件分栏展示。

建议试运行后建立两周基线，按渠道判断哪些素材带来有效试听和平台点击。本文不设没有历史依据的增长目标，也不承诺网站改版提高平台推荐。

### 9.4 数据最小化

统计不采集歌词内容、支付凭证、完整 referrer 查询串、私有媒体 URL 或原始 IP。设备仅记录大类。首期平台排序由后台与用户主动选择决定，地区统计默认不开启。

需同意的统计按既有隐私机制执行，拒绝后网站播放和跳转正常使用。事件队列有上限，统计接口故障不阻断核心操作。建议原始事件保留 90 天、聚合报表保留 12 个月，具体周期与账号删除规则在上线前记录到政策与配置中。

## 10 内容后台与日常运营

### 10.1 后台模块

复用现有管理入口，扩展歌曲、推广歌曲专门配置模块、发行平台、短视频、MV、游戏、首页配置、推广 Campaign、统计和迁移清单。推广模块服务于个人品牌展示与平台导流，歌曲主要在各音乐平台发行。不建设第二套后台账号。最小角色为内容编辑与可发布管理员，所有发布、下架和回退记录操作人。

歌曲编辑支持封面、公开音频模式、试听文件、现有完整资源引用、歌词、介绍、语言、发行日期和相关作品。平台编辑支持状态、真实 URL、地区限制、排序与核验日期。视频管理保存源素材及各渠道发布记录，便于复用和追踪。

### 10.2 推广歌曲配置模块

在既有后台设置专门模块，由运营者逐曲启用或停止推广，管理主推顺序、是否提供站内公开试听、独立试听资源、已核验平台入口、关联短视频与 Campaign。首页主推与推广链接使用该模块的有效配置，歌曲资料、平台状态和素材仍复用已有内容记录。

站内试听是可选推广能力。开启试听时，公开资源必须已就绪且使用权限已登记，游客无需登录；未开启时，作品页展示品牌内容、歌曲介绍和真实平台入口，不承诺站内试听。已有完整播放与会员校验保持独立，不因推广启用而改变权益。

推广配置沿用后台角色权限、revision、发布审计及缓存更新机制。无已上线平台时显示准确发行状态，不填充虚构链接。网站公开作品页、推广启用和外部平台发行分别管理。

### 10.3 发布流程

运营者录入歌曲与真实平台发行状态，完成资源校验和权利登记，在推广歌曲模块选择推广作品、配置试听开关及资源、平台入口与关联素材，预览手机与桌面页面，再公开网站作品页及推广配置。网站内容公开不代表歌曲在本站发行或必须提供完整音频。随后创建 Campaign 链接与二维码，在短视频渠道发布，回填实际发布链接。Apple Music 后续上线时，只更新已核验的平台记录，歌曲长期地址与推广二维码继续有效。

定时发布需要任务执行幂等，并在失败时保留草稿状态与错误原因。外链检测不能只依靠 HTTP 返回值，平台登录页或风控会影响结果；自动检测只提示异常，管理员确认后更改发行状态。

删除媒体前检查歌曲、短视频、订单和历史版本的引用。线上引用存在时禁止物理删除。下架用状态变更，清理任务留待引用解除与保留期结束后执行。

## 11 技术实现原则与启动检查

优先在现有项目内实现，不因改版更换框架、数据库、账号或部署平台。新增媒体协调层、内容查询层和发布字段，保持其边界明确。页面使用现有服务端渲染或静态生成能力输出单曲标题、封面、描述与平台入口，避免搜索爬虫只看到空壳。

开发第一步提交仓库盘点报告，至少记录：框架与依赖版本、路由树、语言规则、CMS、数据库迁移方式、鉴权、支付回调、媒体存储、会员校验、收藏位置、游戏启动与存档、测试命令、构建与发布方式。依据代码和配置写结论，不能把讨论中的功能当作已经实现。

检查所有调用旧栏目和地址的客户端、邮件、二维码、站内链接与外部 App。列出保留接口与服务页面；不因为其名称包含 apps 或 points 就直接移除。若现有架构不足以支持某项 P0，提交具体受阻原因和最小改动方案。

数据库优先采用新增字段和新增表，先部署兼容旧版本的读取，再启用新界面。旧字段和旧表延迟清理。试听、视频与歌词的公开访问和受保护资源分开配置缓存。

## 12 旧内容退出与搜索迁移

建立逐 URL 清单，覆盖所有语言版本、分页、详情、下载入口及 sitemap 条目。每个旧地址指定 keep、redirect、retire 或 service 四类动作。旧公开入口在新版开发完成并上线后执行关闭，开发期间保持现网可用；上线后不继续公开运行被替代的旧页面或旧导航。保留作品若更换地址，旧地址只做对应内容重定向；无替代内容的旧公开页面返回 404 或 410。有效游戏运行地址与账号、支付、授权、存档及支持服务不作为退役公开栏目关闭。只从菜单移除无法完成内容退出，旧公开地址与搜索索引也需要处理。

| 旧地址类别 | 处理方式 | 验收方式 |
| --- | --- | --- |
| 音乐和游戏且地址不变 | keep 原地址继续可用 | 状态 200 内容正确 |
| 保留内容迁到新地址 | 301 或 308 到对应内容 | 无链式跳转 无循环 |
| 小说 文章 工具且无替代内容 | retire 返回 404 或 410 | 页面提示与 HTTP 状态一致 |
| 支付回调 授权接口 售后服务 | service 保留或专项迁移 | 客户端与历史用户验证 |
| 已更名的歌曲 slug | 301 或 308 到新歌曲地址 | 同歌曲 ID 分享有效 |

Google 官方建议已删除且没有迁移内容的 URL 返回 404 或 410，并避免大量无关旧页面跳到首页。[3] 不通过 robots.txt 阻止访问来代替删除状态。更新站内链接、canonical、hreflang 与 sitemap，仅提交正式公开页面。

每首歌包含独立 title、description、Open Graph 封面与规范地址。歌词和标题正确转义。预览与草稿加 noindex 且要求鉴权；noindex 单独使用不能保护私密内容。平台状态变化与内容下架后同步刷新缓存。

删除前导出旧内容和引用关系，验证备份可恢复。归档备份不在新版公开入口展示。保留订单、余额、用户授权和存档数据，不执行全表清空或批量删除账号。

## 13 安全与非功能验收

管理接口检查实际管理员权限，公开接口只返回允许字段。富文本、歌词和说明进行转义或受控净化，禁止注入脚本。外部视频嵌入使用域名允许列表。服务端链接检测需限制地址和网络目标，防止任意 URL 触发内部网络访问。

统计请求限制批次数、体积、事件类型和速率。客户端时间不可信，服务器保存接收时间并标识异常；来源参数和浏览器上报的国家、会员、游戏就绪等信息不可作为授权依据。服务日志去除私有播放凭证和敏感查询参数。

本期建议验收预算为：手机模拟网络下首页和歌曲页 LCP 不高于 2.5 秒、CLS 不高于 0.1；有足够线上样本后再检查 p75 INP 不高于 200ms。上述为项目目标，实验室指标与真实用户指标单独报告。媒体正文按需加载，首屏不预加载完整歌曲和整组视频。

至少实测 iPhone Safari、Android Chrome 和桌面 Safari、Chrome、Edge 的当期稳定版本，发布测试报告注明版本与设备。抖音、微信等内置浏览器验证试听、视频、链接复制与外站跳转的降级路径；不能保证外部 App 唤起，失败时保留 HTTPS 链接和复制操作。

| A17 | 上线前隔离预验及上线后确认旧公开入口与旧游戏链接 | 上线后被替代旧页面关闭 正确 404 410 或对应重定向 有效运行与服务接口保留 |
| A18 | 内容编辑并发发布 | revision 冲突被识别 已发布版本可恢复 |
| A19 | 拒绝统计或禁用存储 | 播放与跳转可用 统计按政策处理 |
| A20 | 管理员撤销视频或平台链接 | 公共缓存更新 首页无失效引用 |
| A21 | 手机内置浏览器跳转失败 | HTTPS 链接与复制入口可用 |
| A22 | 键盘与读屏操作 | 焦点顺序清楚 弹层关闭后焦点返回 |

测试以核心状态和权限行为为重点。迁移、播放互斥、发布权限和归因去重使用自动化验证；真机音频、内置浏览器及无障碍做人工验证。测试不能仅检查按钮存在就认定功能成功。

## 16 上线与回退

上线前完成数据库与旧内容备份、权限回归、媒体资源校验、路由清单审核和平台链接抽检。在隔离环境演练一首真实歌曲的推广配置、网站作品页公开流程和一份测试存档的恢复。新版开发完成并上线后，按清单直接关闭被替代的旧公开入口；旧前端仅保留为受控回退版本，不作为正常公开入口并行运行。数据库变更兼容回退版本。

上线后持续观察接口错误、播放失败、游戏就绪与存档失败、外链异常和关键页面 404。账号、历史权益或存档发生损坏时立即停止扩大灰度并回退；第三方统计不可用时先关闭统计，播放与游戏继续运行。

回退可恢复旧界面和内容配置，已迁移的新数据保留。涉及付款、存档或用户新写入的数据，不直接用旧备份覆盖生产库。不可逆字段或表删除在灰度稳定及保留期结束后另行安排。
