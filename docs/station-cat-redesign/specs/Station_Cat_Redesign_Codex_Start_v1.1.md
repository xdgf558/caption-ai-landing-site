## 1 可直接粘贴的首次启动指令

请在当前 Station Cat 网站仓库实施音乐与游戏改版。先完整读取项目 AGENTS.md、项目说明、配套开发文档和实施任务清单。遵循现有仓库约定，在现有框架内改造，并把实际代码与本文建议的差异写清楚。

这次改版以个人品牌推广为主要目标，产品范围为音乐与游戏。大部分歌曲在各音乐平台发行，网站提供官方作品展示、推广内容与平台导流。首页展示品牌入口、主推歌曲、音乐短视频与主推游戏。推广歌曲由既有后台的专门模块设置，管理推广启用、主推排序、独立公开试听开关与资源、平台入口、关联视频和 Campaign。单曲页按配置提供免登录试听，未开启试听时以歌曲内容和真实平台入口为主。游戏页面负责了解玩法、开始及继续游戏。账号、订单、余额、已购权益、存档和支持服务继续有效。

从实施清单中尚未完成的下一个任务开始，每项提交 PR 并等待用户审查通过后再进入下一项。T01 至 T03 分别负责以下范围：确认当前仓库与实际域名 wwwstationcat.org 的对应关系；定位技术栈、路由、语言、后台、数据库、账号、支付、媒体、收藏、游戏与存档；列出旧内容退出规则、服务依赖、权限矩阵和最小素材缺口。每项结论附真实代码位置，区分实际能力、页面文案和未知事项。不要读取或输出私密配置值。

完成盘点后，前端设计必须直接调用 product-design:index 与 product-design:ideate，先提供 3 个具有明显差异的可视化 UI 模板让用户选择；用户选定后按逐项顺序实施 T04、T05 的前端视觉与导航。未选定前只处理当前任务的无依赖准备，不跳到 T06。交付按选定模板实现的可运行隔离预览与可审阅改动。样例内容只用于隔离预览，生产入口只展示真实已发布记录。不要把文档中的示例 API、slug、平台 URL 或建议路径直接当作现有实现。

优先复用现有播放器、账号、会员校验、管理后台和对象存储。不要建立第二套账号，也不要借本次改版更换数据库或支付方案。会员规则有差异时以当前生效行为为依据记录差异，本任务不变更价格、期限和权益。

首页与推广单曲页首次加载保持静音。统一协调音乐、短视频、MV 和进入游戏的媒体状态。关闭视频或退出游戏后保持音乐暂停。外站按钮不等待统计完成；发行状态未上线时不提供虚构链接。Apple Music 嵌入播放器按 P1 处理。

先盘点和备份旧内容，按逐地址清单准备关闭规则；新版开发完成并上线后直接关闭被替代的旧公开入口，开发期间不提前关闭，上线后不并行公开运行旧页面。保留有效游戏运行地址和存档作用域，保留授权、支付回调、历史订单与支持服务并接入新版。采用兼容数据库变更，不执行生产数据物理删除、账号清空或旧备份覆盖新存档。

用仓库现有命令完成必要测试和构建。为权限、播放竞态、存档、发布状态、迁移和事件去重验证实际行为。没有运行的测试标记未验证，浏览器模拟不写成真机通过。不要仅因按钮存在就认定播放或游戏启动成功。

遇到已明确的常规实现选择，自行推进；前端视觉模板必须由用户从 3 个可视化方案中选择后再实现。缺少媒体、凭据或无法确定收费与存档规则时，记录具体缺口和影响，继续当前任务中的无依赖准备，不跳过逐项审查顺序。不要扩大范围解决尚未要求的订阅改造、社区或新游戏玩法。

完成当前任务后提交该任务的可审阅 PR 与实际证据，用户审查通过后才进入下一项；说明完成的任务、受阻项、回退方式及后续依赖。仓库支持且本轮授权允许时创建草稿 PR；不要自动合并。实际生产发布按授权范围和仓库规则执行，代码准备、测试通过与生产部署分别记录。

## 3 后续任务范围参考

以下分组仅列功能边界。每次只实施前一项已获用户审查通过后的下一项，不按整组连续执行。

### 音乐路径范围

T06 至 T11 的功能范围如下，实际逐项执行。完成兼容模型（含推广歌曲配置）、公开字段、资源权限、目录、单曲页、播放状态、发行平台入口和短视频。按后台推广试听开关分别验收游客试听与无站内试听场景，平台发行与网站内容公开分开记录。保留旧 ID、已购权益与现有收藏方式。重点验证试听资源隔离、快速切歌、播放被阻止、音视频互斥和统计失败时外链可用。完成后回报 A02 至 A06、A09 至 A11、A15、A16、A21、A22 的实际验证状态。

### 游戏与运营范围

T12 至 T16 的功能范围如下，实际逐项执行。沿用现有游戏运行地址与存档读写，处理有效、损坏、不兼容和不可访问存储。进入和退出游戏与网站媒体协调。扩展现有后台完成上传、编辑、推广歌曲专门配置模块、平台状态、网站内容发布、下架和内容回退，校验服务端权限与并发 revision。推广模块沿用原账号与角色，不建设第二套后台。回报 A07、A08、A13 至 A15、A18、A20 的实际结果。

### 推广统计范围

T17 至 T19 的功能范围如下，实际逐项执行。实现已登记 Campaign、UTM 与旧 src 映射、匿名会话降级、事件去重及报表。依据实际 playing、ended 和运行端就绪确认上报。累计收听时间排除暂停、等待、拖动跳跃和隐藏页面时间；有效试听严格按主开发文档的“前台实际累计至少 10 秒或试听结束”口径，同 playback_id 一次，不另设 90% 阈值。外部点击、外部播放和短视频曝光分开记录，缺数据标为暂无数据。使用小样本人工核算验证聚合及分母。

### 迁移与上线准备范围

T20 至 T22 的功能范围如下，实际逐项执行。先在隔离环境验证逐地址关闭规则，完成 A01 至 A22 的上线前检查（A17 采用隔离预验）、必要设备验证、回退演练和上线材料。新版开发完成并上线后，直接关闭被替代的旧公开入口，核验对应重定向、404、410、语言链接和 sitemap；有效游戏运行地址与账号、支付、授权、存档和支持服务继续可用。旧前端仅作受控回退版本。数据物理清理不在本批执行。准备可审阅 PR、迁移记录与上线条件，发布和旧入口关闭动作依实际授权执行。

## 4 防止错误完成声明

创建了任务文档、接口占位或静态样例时，报告对应准备成果。真实媒体、后台发布、存档和权限路径尚未接通时，相关功能保持实施中或受阻。没有平台实际播放数据就不输出平台播放转化率；缺少游戏运行端确认就不输出游戏就绪率。线上网站仍使用旧版本时，明确交付属于开发预览。
