## 工作区与内容边界

既有音乐后台新增 `/admin/music/content/`，共八个模块：歌曲资料、推广歌曲、发行平台、视频与 MV、游戏介绍、首页配置、素材权利、发布记录。继续使用原 Access 账号和音乐管理入口，页面本身不含私有数据，带 noindex；所有动态管理响应是 `private, no-store`。

歌曲的网站资料、旧完整音频封存版本、外部发行状态分别管理。新建歌曲只建立原音乐体系可继续编辑的草稿和网站草稿，不写旧公开指针、不授权完整音频或会员；初始标题/艺名遵循原后台 120/80 字限制。登记既有歌曲不修改原音频、会员政策或旧权利审批。后续网站 metadata 独立维护，不自动写回旧音频草稿。

推广模块管理启用、排序、独立试听、已核验平台和同歌曲视频。关闭试听保存后清除该版试听引用；保存未启用的推广版本会清除该版所有平台/视频/试听引用。下架只使当前网站发布指针失效，封存历史保留供审核和重新核验后的回退。首页要求引用当前已公开且启用的推广；停止推广、歌曲下架、资源/权利失效后，新请求去掉相应卡片。公开接口和媒体响应使用已有 no-store 策略，不产生新的正缓存，也没有缓存 purge 或部署操作；已在浏览器渲染或缓冲的内容不会被主动远程撤回。

Campaign 面板只显示当前歌曲既有的关联记录。创建、推广地址和二维码属于 T17，尚未实现。主推作品、真实发行链接、试听开关和视频继续“稍后确定”，没有替用户选择。本地夹具不是运营配置。

游戏介绍拒绝 `cat-life` slug，仅可绑定现有 `/games/cat-life/` runtime，要求设备说明、就绪截图和权利登记。既有游戏运行端、存档流程、云写入和支付没有在本批重构。外部视频发布记录保存平台、帖子标识、原地址、时间和操作人，不自动抓取平台或判断发行成功。

## 权限、迁移与开关

`/admin/api/music/site-content/*` 先经过原 Access JWT、允许名单、同源写入与 CSRF 校验；服务只有 `STATION_CONTENT_ADMIN_ENABLED=true` 才查询绑定。管理员默认映射为现有可发布角色；可选 `STATION_CONTENT_EDITOR_EMAILS` 仅将已获原 Access 许可的账号降为编辑，不能引入新账号。编辑可保存网站草稿、登记待发行平台，不能发布、回退、安排定时、审核资源权利或改动已上线平台。发布角色仍可在原后台处理原权益。

新增 MUSIC_DB 一次性迁移 `0014_station_content_operations.sql`，为资源权利添加 `edit_version`，新增 `station_publish_jobs`。它没有内容种子，不改已有 0012/0013 文件或清理视图；`ALTER TABLE` 不可重复执行，应由正式版本迁移器按一次性账本处理，不能放进请求路径重放。

内容服务核对实际 MUSIC_DB 的 0012 账本与清理视图、0013 上传结构/账本及 0014 结构/账本；绑定错误、未升级或不可用返回 503。生产 0012–0014、实际绑定和 R2 均未远程确认，本轮没有远程迁移或生产配置变更。公开查询/页面沿用此前关闭态，不因后台存在而开启。

定时发布另外要求 `STATION_CONTENT_SCHEDULES_ENABLED=true`，两个后台/定时开关缺一时不读绑定。复用已有 Worker scheduled 入口，不新增 cron；每次最多检查三条已到期任务。安排定时先核验一次，执行时重新检查管理员仍在允许名单且具有发布角色、已批准的 revision/edit_version、当前资源与关联。

## 并发、版本与恢复

保存追加新草稿，公开版本继续保留。发布将该草稿封存并切换发布指针；回退复制指定历史封存内容成新的封存 revision，并重新校验当前所有资源、权利和关联，不能通过旧版本恢复已撤销授权。下架和再次保存也需要当前 `If-Match: "edit-N"`。历史版本按 25 条分页，已封存版本可从后台选择回退。

使用原管理 `mutate` 的 D1 batch，将目标行、关联行 JSON 指纹、发布指针、原操作 receipt、审计和定时结果放在同一事务；竞争修改返回 409，失败批次不留下部分指针或审计。[Cloudflare D1 batch 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/) 描述顺序执行与整个序列失败回滚。单个引用图最多 90 个 guard，使用每行一个 JSON 绑定参数控制 D1 参数数量。

D1 事务不包含 R2，也不能与 Access 配置变更跨系统原子提交。发布时检查新鲜 R2 HEAD 的大小/MIME/etag、T15 已验证状态和资源身份，公开请求继续重新校验；HEAD 后到事务提交仍有外部对象变化窗口。这里没有声称逐帧解码、真实版权审核或强制撤回已缓冲媒体。

定时任务绑定原发布者和批准版本。成功时发布指针与 succeeded 状态同事务提交；当前版本校验失败时留 failed/错误码，初次发布回到可编辑草稿，既有公开版本继续显示。保存新草稿、下架或取消会在同一事务取消原 pending 任务。未知 D1 结果保留待核对状态，下轮按原任务键恢复；失败摘要使用脱敏代码，不展示原始异常。

客户端写入前把原路径、原 body、版本和幂等键保存到按管理员分隔的 sessionStorage。结果未知时禁止后续写入，刷新只重新读取，用户点击“核对原操作”才按完全相同的命令重试。身份变化不会把旧账号迟到回执应用给新视图。sessionStorage 不可用/损坏时停止写入；不保存签名、完整媒体地址、上传文件或认证凭证。服务端权限与 CAS 不依赖客户端。

## 发布前校验与范围

发布/回退/定时检查四语言元资料、就绪封面/歌词、同属对象的资产和 approved 权利、未退役状态、公开关联、固定游戏运行地址及实际测量的视频时长。视频也重新核对父歌曲当前资源。试听要求同歌曲独立剪辑、来源就绪、区间与时长合法，不能直接绑定完整音频。`free_full` 必须与旧版本当前免费政策一致；`existing_entitlement` 不授予音乐 VIP，完整播放仍走旧服务逐请求核权。

平台仅沿用 T10 的五个提供者与严格 HTTPS 作品地址白名单，上线要求真实网址与人工核对时间；待发行/下架不输出公开目标网址。每首歌最多 25 条平台记录，每个视频最多 10 条外部发布记录，身份固定；这些记录不等于平台真实播放统计。后台的权利核对是人工登记，不能由合成夹具证明素材可商用。

“核对与预览”只提供私密元资料、关联校验和桌面/窄屏文字排版，不渲染完整生产页面，不播放媒体、不输出对象键或音频地址。列表按 20 条、历史按 25 条、素材按 50 条分页；作品选择可读下一页，所属素材表单最多累积 1,000 份，超出需要通过 API 的 kind 筛选。同歌曲视频和素材权利所属视频/游戏选择也提供继续读取，避免只能选择最近一页。
