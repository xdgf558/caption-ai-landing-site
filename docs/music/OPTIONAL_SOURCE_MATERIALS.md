# 音乐后台来源材料可选

2026-09-13 产品决定：整个音乐后台的来源材料改为可选，涵盖单曲与专辑多文件上传、技术核对和显式发布。本合同取代旧规格中“必须先提交来源/套餐/凭证并通过权利核对”的前置条件；它不把未提供材料转换成已核准授权。

## 记录与发布

| 来源记录 | 技术核对 / 发布 |
| --- | --- |
| 未提供 | 可以继续，保持无权利记录 |
| pending（未核对） | 可以继续，不生成 approved 或权利指纹 |
| blocked（不通过） | 拒绝，返回 MUSIC_RIGHTS_BLOCKED；管理员需显式处理结论 |
| approved（通过） | 沿用原有完整字段、凭证及当前版本指纹核验，不能保存或沿用不完整的通过结论 |

已有记录及凭证保留。材料可留空；若提供证据引用，仍须是本曲已验证的私有 evidence 资产，数量不超过 10，且通过现有资源字节核验。材料和凭证不进入公开投影。可选表单未保存的修改仍需保存或放弃后才能技术核对/发布，避免使用与页面不同的旧结论。

上传仍只产生私有资产。正式发布仍需管理员显式执行，且必须有当前版本的技术核对：完整音频实际试听；有试听时确认短文件已听及与完整音频对应；有封面时确认已查看。服务端继续验证 MP3 实际字节、帧时长、归属、独立试听及源区间，不能用勾选替代结构核验。

## 一致性

指纹格式保持兼容，包含当前来源记录内容、证据集合及资源身份。approved 记录仍要求权利指纹与技术指纹一致；未提供/pending 只要求当前技术指纹。更新记录、证据、素材或草稿会使旧技术核对失效。新增可选材料也不自动继承技术通过。

技术核对与发布的条件事务均核对来源状态：已有记录逐字段比较及证据集合匹配；缺记录时使用 NOT EXISTS。读取后新增 blocked 记录、pending 改成 blocked、证据被替换等竞争会冲突回滚。CAS、幂等回执、审计和发布数量限制继续生效，回执重放不产生第二次发布或权利通过记录。

## 权限与交付

材料状态不授予播放资格。免费/VIP/抢先策略、VIP 独立试听要求、每次 /audio 鉴权、配额、未知 PUT 恢复、Access 和 Cookie 隔离保持原合同。专辑仍逐首上传及发布，listeningMode 不批量改单曲权限。

本包不新增迁移、API、开关或支付逻辑，也不部署或自动发布作品。回退到旧 Worker 后，缺少 approved 材料的草稿会重新被旧发布校验拦住；不删现有数据、不补写通过结论。部署仍按对应维护 runbook 独立执行。

回归覆盖无记录/pending 在 free、VIP、early_access 下的技术核对与发布、明确阻止、缺试听/资源、指纹变化、并发新增阻止记录和回执重放；本地原生 D1/R2 与浏览器覆盖无材料上传到显式发布，匿名 VIP full 仍拒绝。测试仅使用合成夹具，不能充当真实作品或真机验收。执行日志、截图、响应、音频及 session 材料均保留在仓库外，不附带到 PR。
