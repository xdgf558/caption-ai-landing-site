# M2-05A：过期上传清理与配额回收

状态：本地实现与专项验收完成，待复审。基线为 PR #133 / main@1f6181e。

## 范围和维护入口

新增 `0004_music_cleanup.sql`，仅适用于独立 MUSIC_DB。它只增加停用记录、引用保护触发器和计费视图，不删除对象、不修改原上传/资产/审计/幂等记录，不设置正配额。新版上传计费和清理依赖 0004；未迁移时上传 readiness 为不可用。未执行任何远程迁移。

`GET /admin/api/music/cleanup?before=<cursor>` 是只读 dry-run，每页最多 25 条已经到期的会话，返回 canonical objectKey、各类引用依据、保留期、计费状态、写入证明需求和 planHash。它不遍历 R2、不读文件内容、不修改 D1。R2 存在性和对象身份在执行阶段检查，因此 dry-run 不是“文件已可安全删除”的承诺。默认最小保留期为会话到期后 7 天。

`POST /admin/api/music/cleanup/:uploadId` 每次只处理一项，JSON 为 `{ "planHash": "<dry-run 返回值>", "reason": "维护原因" }`。复用真实 Access JWT、同源 Origin、自定义请求头、Idempotency-Key 和 private/no-store。服务器只接受上传 ID，不接受客户端 objectKey。执行还要求独立维护开关 `MUSIC_CLEANUP_ENABLED=true`，缺省关闭；未加入生产或预发配置。只读 dry-run 无需开启执行开关。此批没有自动定时执行，也没有修改 Signal cron/queues。

## 删除与计费合同

执行先比较 dry-run 的完整上传/资产快照，然后以 D1 条件事务写入永久停用记录。事务内重查引用；触发器同时禁止后续修订、证据、权利记录、派生素材和实质审计重新引用该资产，也阻止旧上传会话开始/完成。所有历史修订（包括旧草稿、下架和归档版本）都保留其引用。已停用的派生素材不继续占用源音频引用；尚未停用的派生素材会阻止源音频清理。未通过上传会话登记的旧资产仍计费，自动清理不处理它们。

上传与清理的生命周期审计只保留元数据，不代表文件必须永久保留；这些记录全部留存。权利/发布等实质审计中的资产 ID 或 evidenceIds 会阻止清理，即使当前权利表已不再引用它。

无迟到写入风险仅允许两种证明：

- `never_started`：原会话从未取得 write_token，停用事务阻止它此后取得写入权，并确认 R2 中没有该对象。
- `object_observed`：会话已经取得唯一写入权，R2 实际存在且身份、大小、MIME 与上传登记匹配的对象。持久化其 version、ETag 和大小后才允许删除。既有上传协议每个 key 只执行一次 PUT；重试只查询/complete，不会再次 PUT。

已开始写入但 R2 缺失时，不能用“过了 7 天”或一次 HEAD 当作写入已经结束。返回 `CLEANUP_WRITE_UNCONFIRMED`，保留全部 charge；若迟到对象随后出现，可以使用原 planHash/reason 恢复。如果始终无法证明写入结果，这项预留会一直保留，需后续独立维护处理，不能手删会话或改计费视图强行释放。

删除前再次检查当前对象的 version/ETag/大小以及 D1 引用；删除后再次 HEAD 确认缺失，最后通过条件事务写入 released_at、审计和幂等回执。计费视图只有看到 released_at 才扣除整笔预留。删除异常、超时、回执丢失或末尾数据库失败均不提前释放；保存的证明允许重试从“已删除、未记账”恢复。并发执行可重复删除同一已停用 key，但只释放一次额度、只生成一条回收审计。

R2 的 [Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/) 提供强一致 HEAD/PUT/DELETE，但 delete 不接受 ETag 条件。这份方案依赖受控私有桶中的唯一上传写入者、永久 D1 停用记录和存储证明；执行维护期间不得另用 S3/控制台覆盖或恢复相同 key。它不声称 D1 与 R2 具有跨服务事务。

## 回滚边界

0004 是追加迁移，不回退 schema、不清除停用/证明/释放记录。旧代码仍按原预留全额计费，会保守高估已回收额度；不能以删除会话修正。旧上传/引用写入也受新触发器约束。可以关闭维护执行开关停止后续清理；这不会恢复已删除的对象。
