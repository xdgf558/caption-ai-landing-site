# M4-03 歌词与本机记录

本切片延续 M4-02 的纸感曲库与手机详情面板。新增四语歌词、收藏夹、最近播放、暂停状态下的位置恢复及本机记录管理。只接现有公开读取接口；公开总闸、逐次 `/audio` 核验、单一 audio、队列及 M3-03 卸源守卫保持。实现不包含部署、迁移、开关、会员账本或后台上传改动。

## 歌词

目录只接收 `instrumental` 布尔值和 `lyricsKind: none | txt | lrc`，不接收媒体 URL。展开歌词后按已验证的曲目 ID 与 `audioVersion` 构造同源 `/api/music/tracks/{id}/lyrics?v={audioVersion}`，`no-store`、拒绝重定向；响应必须为 200、`text/plain` 和有效 UTF-8。声明长度与流式读取均有 128 KiB 上限，请求超时 8 秒。切换查看对象、折叠或销毁会取消请求，迟到响应不能覆盖新曲目。歌词仅暂存在当前面板内存中。

TXT 原样按文本显示。LRC 接受 `[mm:ss]`、百分秒/毫秒、连续多个时间标签和全局 `[offset:毫秒]`；正 offset 表示提前显示，即从时间戳减去 offset。按时间排序，同一时间合并不同文本，非法行跳过；没有有效标签时降级普通文本。文件最多 5,000 行，展开后的时间行也最多 5,000 条，拒绝 NUL。所有内容使用 `textContent`，不执行 HTML、脚本或自动链接。解析器给出警告数量；后台逐行警告界面归 M5，当前播放器不代替后台上传审核。

当前行只根据内核提供的真实媒体进度计算，试听加 `previewSourceStartSec`。只有查看的曲目和版本都与当前音频一致才高亮，查看 B 不切换 A。手动滚动、触摸、拖动滚动条或滚动按键会停止自动跟随，“回到当前歌词”恢复；程序只滚动歌词容器。歌词区 `aria-live=off`，不用逐行播报。纯音乐单独显示“这首作品为纯音乐”，缺词显示“暂未提供歌词”，两者都不请求歌词；错误保留在当前曲目/版本上，进度刷新或折叠再展开都不自动重试，点击“重新加载歌词”才重试。切换曲目或歌词版本可开始新的读取，失败不影响音频。

VIP 封面与已发布歌词仍遵守 M2 的匿名展示合同；歌词请求不授予音频权限。

## 本机数据合同

只写 `stationcat.music.v2`，输入最大 512 KiB，白名单如下：

| 字段 | 内容与边界 |
| --- | --- |
| schemaVersion | 固定 2 |
| favorites | 去重曲目 ID，最多 500；顺序为收藏顺序 |
| recent | 去重曲目 ID，最多 50；真实 `playing` 后才更新，最近在前 |
| queue | 队列顺序的曲目 ID，最多 500 |
| settings | volume、muted、shuffle、repeat；类型和取值校验 |
| positions / current | trackId、revisionNo、variant、assetVersion、positionSec、savedAt；最多 1,000 个版本/variant 位置及一个当前位置 |

今天的公开 `audioVersion` 是不可变的发布修订选择器，`/audio` 与 `/lyrics` 均使用它。本地 `revisionNo` 和 `assetVersion` 都绑定此值；后者表示当前公开媒体选择器，并非另一个 R2 资产版本或存储 key。若以后公开独立资产版本，应显式迁移该键，不能混用旧进度。full 与 preview 分开保存，版本或 variant 不同不复用位置。未来时间、非法值和超过 30 天的位置不恢复，收藏不会按时间过期。

不保存曲名/封面/歌词/媒体 URL、账户身份、Cookie、令牌、VIP 标志、到期时间或资格响应。未知字段不进入新记录。本机键独立于小说和游戏存档，不做跨账号、跨设备同步；多标签页没有记录合并协议。

只在实际开始播放后记录进度，播放中按 5 秒节流，在暂停、切源、状态变化及 pagehide 尽力保存；正常播完保存零位置。队列和设置变化可单独保存。存储不可用或写满时停止磁盘写入，使用本次内存状态，并提示无法保存，播放不受阻。

## 读取、恢复与迁移

首次目录与资格读取完成后才尝试恢复一次；首次目录失败后，手动或回前台成功重试也能完成恢复。队列 ID 通过新目录解析，目录外条目不进入可播放队列；收藏/最近记录仍保留，并提示目录外数量。收藏、最近仍可叠加搜索、标签、访问类型与歌单筛选，浏览不会重建播放队列。清理入口位于筛选里的“管理本机记录”。

URL 明确选择优先于上次曲目。新的 variant 来自当前目录和资格，存储数据不决定 VIP。恢复只做无源选择、暂停及待恢复位置；`src` 保持空，音频请求和 `play()` 仍等用户点击。metadata 到达后才将位置限制到实际 seekable 范围。用户在首次读取结束前已选曲、播放或调整设置时，以用户操作为准，不覆盖为保存状态。

仅当没有 v2 时读取 v1。兼容形状为 `schemaVersion: 1` 加 ID 数组 `favorites` / `queue` 和白名单 `settings`；只迁移校验通过的上述字段，不恢复旧进度、当前曲或资格。v1 原文保持原键并可导出，写 v2 失败也保留。JSON 损坏、不认识的 schema 或容器结构错误时，不覆盖原文本，提示并进入内存模式，可先导出原始记录。导出只生成用户本地下载，不上传。

“清除本机音乐记录”需要用户确认，清除这两个音乐键及当前内存记录；不停止正在播放的音频。之后新的实际播放/进度仍可产生新记录。清除存储失败会提示，不能宣称磁盘已清空。

## 本地复现与验证范围

```sh
npm run test:music:lyrics-local
npm test
npm run build
npm run build:music:player-preview
MUSIC_LIBRARY_PREVIEW=true MUSIC_PLAYER_PREVIEW_SCENARIO=lyrics-local MUSIC_PLAYER_PREVIEW_PORT=4213 node scripts/serve-music-player-preview.mjs
```

`lyrics-local` 使用原创测试文本与合成 WAV；包括 TXT、LRC、纯音乐及从原曲第 12 秒开始的试听。`lyrics-error` 返回歌词错误，`lyrics-large-text` 放大根字号。服务仍只监听 127.0.0.1、检查 Host 与 GET/HEAD，固定假资格，不代理云端。测试覆盖解析和大小限制、迟到响应、手动跟随、迁移与存储失败、版本/variant 隔离、真实播放记录、恢复无 src/play、用户操作优先及重试恢复。

设计图、截图、日志、执行报告与 session 材料仅本地保留，不进入本 PR。桌面浏览器尺寸/200% 根字号检查不代表 iPhone 或系统大字验收；真实媒体、Safari、会员到期真机和锁屏仍归 M6。下一开发项 M4-04 分享与会员回跳；M5 的 WAV 转 MP3、整张专辑上传与会员专享配置仍独立推进。
