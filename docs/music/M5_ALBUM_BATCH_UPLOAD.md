# M5-01B 专辑多文件上传

基线：#149 已合并为 main@cbbb975。只新增浏览器批次编排和后台入口，复用既有曲目、上传、集合 API；无 Worker、迁移、配额、开关、VIP/支付或部署改动。0006/0007 远程迁移及预发入口/资产白名单仍独立走 runbook。

## 操作合同

从已保存的草稿专辑进入 `/admin/music/collections/upload/?album=<UUID>`。资料或曲序未保存时不能进入；歌单不提供入口，已发布专辑必须先下架。上传过程中其他窗口改变专辑版本、成员或发布状态，会阻止继续和写入曲序。服务端原 Access、Origin/CSRF、管理员、上传开关、配额、格式验证、CAS 和幂等仍是最终边界。

每批 1–50 首、原文件总计最多 1 GiB；可多批加入最多 500 首的专辑。只选择 MP3/WAV 多文件，不支持 ZIP、目录导入、长音频切轨、自动识别 ID3 资料或自动生成试听。MP3 每首 32 MiB；WAV 每首 256 MiB / 20 分钟，输入和固定编码合同沿用 M5_WAV_TRANSCODE。浏览器只处理一首、一个转换 Worker、一个上传请求；转换结果在当前处理结束后释放，不同时保存整张专辑的 MP3 输出。File 引用、Blob/编码器的浏览器内存开销不等于本合同的文件大小上限。

先填写共同署名、原文语言、歌曲语言和器乐说明，再生成清单；这些是新草稿资料，后续可逐曲完善。曲名从文件名建议，允许编辑；曲序用上移/下移调整。选择文件和生成清单均不转换、不 POST。每行必须明确选择免费或 VIP，没有自动继承专辑 listeningMode，也没有批量修改已有单曲权限的接口。抢先听等更完整策略由原曲目工作区设置。开始后冻结本批资料、权限与顺序，防止恢复期间改变命令。

点击确认后依次执行：本机转换（若为 WAV）→ 增量 SHA-256 → 新建曲目草稿 → 原上传 API 预留 → PUT → 服务端 complete/MP3 核验 → 用新建时的草稿版本关联音频。只对本批新曲目操作；不采用服务器最新草稿来覆盖并发编辑。失败在当前行停止，不自动重试，不偷偷跳过失败项处理下一首。点击“继续批次”才恢复；可以取消未创建草稿的项后继续。

完整音频验证且关联成功才计入“草稿完成”。管理员另行点击“将成功曲目加入专辑”，确认实际完成数，才能用原集合曲序 PUT 把成功项追加到基线成员后。这是显式的曲序写入，不是整批事务或发布。可先加入部分成功项；再次加入时，本批成功项按冻结清单重建顺序，已有基线成员顺序保持。失败或尚未开始的项留在清单，未加入项不计作已完成的专辑。

若别人修改专辑，默认不覆盖。管理员可明确“核对服务器曲序”：重新读取草稿专辑，采用当时服务器的成员及顺序为新的追加起点。已在该顺序中的成功曲目不重复添加；之后的成功项追加在末尾。此显式重新核对可能保留与原清单不同的已有曲序，界面确认文字说明这一点。读后再发生并发修改仍由 If-Match 拒绝。

每行提供带 UUID 的曲目工作区入口，打开当次服务器详情。原曲目工作区若有未确认写入，不消费其 journal 或覆盖该操作；有未保存编辑先提示。仍需逐首填写分类、简介、独立试听、封面、歌词、权利和技术审核，并分别发布曲目，再按专辑整张一致性条件发布。上传不签发 `/audio`，也不改变 VIP 封面/歌词公开展示合同。

## 故障恢复和取消

恢复记录独立于曲目、集合编辑及用户收听偏好：`station-music-album-batch:v1:<actor>:<albumId>`，仅 sessionStorage。保存清单文字、顺序、逐曲策略、UUID、版本、输出大小/哈希、固定转换配置及未确认命令的原键；不保存 WAV/PCM/MP3 字节、Cookie、Access token 或媒体 URL。账号和专辑隔离；存储不可用、记录不合法、命令与清单不符时失败关闭。刷新只恢复清单，不自动转换或写入，关闭标签页不保证恢复。

| 失败点 | 恢复方式 |
| --- | --- |
| 转换失败或取消 | 不创建该项的草稿或预留；可重选文件后继续。已有原预留不释放 |
| 新建、预留、complete、关联草稿、曲序回执未知 | 锁住后续写入，明确核对原操作；重用原内容、版本和幂等键。一次持久化同时接收回执并清原键 |
| 已确认 reserved 且尚未发出 PUT | 重选相同 MP3，或原 WAV 按原配置转换；大小与哈希均相同才允许发送 |
| 已经开始 PUT（即使请求尚未到达服务端） | 先 GET，再 complete；不再 PUT。一次 reserved / 空对象观察不能证明迟到请求不会提交。仍无法确认则保留清单与原预留，进入维护跟进 |
| 上传已 completed | 不要求文件、不加载编码器，只恢复验证/草稿关联 |
| rejected、expired、retired | 记录终止状态，不创建替代预留。已占额度、对象和会话仍按原维护流程处理 |
| 账号变化 | 当前写入前核对失败；原账号恢复后，可明确重试原操作。转码结束及 PUT 前也重查身份 |
| 草稿或专辑版本冲突 | 保留完成结果和恢复记录；不自动读新版本强行覆盖。专辑可显式采用服务器曲序，曲目冲突须回原工作区人工核对 |

“停止后续／取消转换”可立即终止本机转换；PUT 已发出时等待当项验证/关联结束（或失败），不启动下一首，也不声称上传已撤销。“取消未开始项”仅取消未创建草稿的行。已创建的草稿、已预留/未知结果的项不允许通过取消或结束清单绕过恢复。

结束此批次只清本标签页：未确认操作、未完成已创建项、未加入专辑的成功项均阻止结束。已确认终止的 rejected/expired/retired 项可随结束清单移除本地展示，但服务端会话/审计/额度不会删除或回收，仍需管理维护。无文件字节持久化、无跨标签同步、无 cron、无自动删除。配额显示随身份核对刷新，预留仍使用服务端原子配额检查。

## 验证与运行

`npm run test:music:album-batch` 纳入 `npm test`：覆盖无默认权限/输入边界、顺序与单请求、逐阶段丢回执、未知 PUT（包含服务端仍 reserved）、原文件哈希、账号切换、存储失败、取消、部分成功、曲序并发和恶意恢复命令。已有上传、MP3/WAV、后台客户端和专辑测试保持。

`batch.spec.mjs` 纳入现有 music-admin browser CI，在临时 D1/R2 中验证 MP3/WAV 混合完整链路、逐曲策略、顺序、显式添加、详情回到正确曲目、丢预留原键恢复、丢 PUT 不重传、窄屏及取消、账号恢复。沿用原真实 MP3 与合成 WAV 夹具，不发布媒体或权利。

本机入口沿用 `npm run build` 后运行 `scripts/serve-music-admin-preview.mjs`，临时假身份和配额仅供隔离测试，禁止部署该测试 Worker。新路径、CSS、脚本及转码依赖尚不在预发精确白名单中；旧 staging 打包器继续拒绝未知依赖，不能改成整站资产放行。后续预发按 M5_ALBUM_MANAGEMENT 与 MUSIC_STAGING_HTTP 的关 public、迁移、精确白名单、Access 验收顺序执行。

本地执行记录、截图及 session 材料不进入 PR，即使脱敏也不上传。桌面/390px 模拟视口及合成 WAV/MP3 不代表 iPhone、Safari、微信、真实 Access、云端迁移或真实媒体验收，均仍属 M6/独立预发任务。
