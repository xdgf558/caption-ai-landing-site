# M5-03A 专辑模型与管理

基线：#146（统计）、#147（分享卡片）、#148（后台 WAV 转 MP3）已合并，main@9e51b4c。本切片提供独立专辑类型、管理资料与曲序、整张发布条件，以及四语曲库的专辑浏览和分享链接。整张多文件上传属于 M5-01B；四角色预览与人工主推仍是后续任务。

## 模型和权限合同

0007 只扩展 MUSIC_DB 的 music_collections；旧行默认为 playlist，不迁移曲目权限、不创建会员或上传会话。collection_type 一经创建不可改，现有歌单继续使用自己的公开过滤规则。

| 字段 | 含义 |
| --- | --- |
| type | playlist 或 album，创建后不可变 |
| listeningMode | mixed 沿用各单曲；free / vip 要求每个成员当前有效权限一致。歌单只能 mixed |
| coverTrackId | 专辑成员曲目 ID 或 null；发布时指定成员必须有已发布的有效封面。null 自动使用曲序中第一个有封面的成员，无封面则使用无图展示 |
| trackIds | 管理端完整有序快照，最多 500，拒绝重复、未知和已归档曲目 |

free / vip 是专辑发布的一致性条件，不会批量改写单曲策略。会员专享专辑仍逐首请求 /audio；完整音频走既有实时会员检查，封面/已发布歌词仍可匿名读取。试听结束即停、自动队列仅完整曲、资格变化卸源等 M3 规则不变。

草稿专辑可以未配齐曲目。发布或更新已发布专辑时，每个成员都必须已发布、指向 sealed 发布版，且符合所选收听范围；不能只检查“至少有一首公开”。每次公开投影重新核对全部成员。任一成员下架、损坏、指定封面失效，或 early_access 自然到期后不再符合整张范围，则隐藏整张专辑；不自动下架其他成员，不把剩余几首冒充整张。普通歌单仍过滤不可用成员，非空即可展示。

封面复用已审核的成员曲目封面，不新增独立专辑封面上传/权利通道。移除指定封面成员前须先更换或清空指定封面。

## 管理流程与事务

入口 /admin/music/collections/，从现有音乐后台进入，继续由 Worker 全局 Access 门禁保护。复用 /admin/api/music/collections 的列表、详情、创建、PATCH 和 /tracks PUT；列表增加 type 过滤。四语标题/简介、语言、链接标识、收听范围和封面均由服务端白名单校验。

先保存资料，再从现有曲库添加成员并保存曲序。可拖动或使用上移/下移按钮；查找每页 50、曲序最多 500。资料与曲序分开保存，未保存状态禁止发布；已发布资料/曲序保存有显式确认，发布/下架/归档要求操作说明。首版不支持从已归档恢复，不提供批量发布或 ZIP 导入。

写入沿用管理员、路由、请求内容绑定的幂等回执、If-Match 编辑版本和 D1 primary 事务。整张元数据/旧曲序/必要的 catalogVersion 与成员发布指针、生命周期、发布时间都在写入 guard 内重查；sealed 版和引用资产保持不可变。任何零命中均回滚业务、审计和回执；删除旧曲序、写入新曲序和审计/回执不是独立提交。原来未提供新增字段的歌单命令保持原规范化哈希形状，可用原键重放。

权限检查以当次服务端时间为准。自然时间边界可能紧邻提交，公开读取仍会重新计算 effectiveAccess 并隐藏不匹配专辑；专辑发布状态和读取资格不能替代音频授权。

专辑工作区使用独立、按管理员隔离的 sessionStorage 恢复记录 station-music-collections:v1，不覆盖曲目/上传工作区的未确认操作。只保存编辑资料、成员 ID/展示信息与原操作，不保存媒体字节、Cookie 或 Access token。结果未知时阻止新写入；刷新不会自动重试，必须明确核对原操作，沿用原内容、版本和键。存储失败或账号变化阻止写入；原站收听偏好 stationcat.music.v2 白名单不变。

## 公开浏览与兼容性

公开 JSON 仍为 schemaVersion 2，集合追加 type；专辑再包含 listeningMode、coverTrackId、coverUrl。白名单不输出 object key、hash、权利材料或身份。浏览器忽略目录提供的任意封面地址，只从校验后的成员 ID/audioVersion 构造同源封面路径。

“专辑”标签仅展示 type=album，点开后按曲序浏览，不播放、不替换当前队列。播放全部仍按现有资格过滤完整曲；专辑链接沿用 ?collection=slug 的安全本站分享/会员回跳协议。没有新增专辑图片卡片或逐专辑 OG；逐曲分享卡片保持原合同。

目录继续保持 500 曲 / 500 集合边界。全局目录窗口外的成员会使该专辑不出现在目录概览中；通过现有集合直达接口可读取整张最多 500 曲。此版本没有专辑独立分页搜索，不承诺目录概览覆盖无限历史专辑。显式直达的错误会显示不可用，不回退成第一首或部分专辑。

## 验证入口和预发顺序

npm run test:music:albums 覆盖类型迁移、全部成员与当前权限、封面、自然到期、并发下架、回执和零写入回滚；test:music:collections 保留旧歌单行为，test:music:library 验证分类/固定曲序/浏览不改音频。test:music:runtime 在 workerd 的原生 D1 执行 0007、发布、回滚、公开投影和 VIP 音频拒绝。现有 music-admin browser CI 增加新建/排序/恢复/账号变化/窄屏与发布拒绝流程。

本包不部署、不远程迁移、不改预发白名单、配额、开关或生产绑定。后续部署必须另行安排：

1. 按 MUSIC_STAGING_HTTP.md 先关闭 public，核对隔离库、备份和版本。
2. 用 Wrangler 正式迁移流程按序应用待应用的 0006/0007，保留真实回执；不能改已应用迁移或手填回执。这里只验证了本地 D1，不能声称远程 SQL 切分器已验收。
3. 新后台路径、样式及拆分脚本尚未纳入隔离预发资产/入口白名单。旧 build:music:staging-assets 会因新增依赖拒绝打包；须在独立预发任务中更新精确白名单并验收 Access、依赖与匿名拒绝，不能直接部署主站完整产物代替。
4. 公共读和真实成员内容仍按独立权利、额度、限流与身份验收清单决定是否开放。

缺 0007 时专辑管理读取/写入失败，不自行建表或回退为歌单。回退 Worker 不撤销 D1 schema；旧代码不理解 album 的完整性条件，可能按歌单显示部分成员，因此回退前须关闭 public，并停止专辑相关管理写入。恢复兼容版本、迁移和校验后再按独立开闸流程处理。

本机合成夹具与响应式检查不等于真实媒体、真实 Access、iPhone Safari、微信或 X 验收；这些仍归 M6。本地截图、执行记录和 session 材料不附在 PR 中。
