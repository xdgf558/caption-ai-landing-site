# M5-03B 人工主推与管理收尾

基线：M5-01A/#148、M5-03A/#149、M5-01B/#150 和 M5-02/#151 已合并。本切片补齐首页人工主推、次级推荐、歌单/专辑推荐和管理端编排，并复用已有公开目录、播放器、资格和审计边界。

## 推荐合同

- 首页只有 1 个主推位、最多 6 个次级曲目和最多 6 个歌单/专辑；保存的是目标 ID 和顺序，不复制作品资料或权限。
- 主推必须是当次有效、已发布且免费完整收听的单曲。次级推荐允许免费或 VIP 单曲；集合允许已发布的歌单或专辑。
- 公开目录每次都根据当前发布投影过滤推荐。目标下架、损坏、提前访问自然到期或专辑失去整张完整性时，失效位立即从公开投影消失，不需要运营先清理配置。
- 主推失效时，先从有效次级推荐中取第一首免费曲；仍没有则显示最新免费曲。响应显式返回 `primarySource`，界面将最新曲标成“最新免费”，不冒充人工主推。无任何免费曲时不显示主推卡。
- 推荐只决定展示与排序。卡片播放复用单一 audio 内核和既有队列；查看另一张卡不会换掉当前音源。VIP 仍逐次请求 `/audio` 核对，推荐字段、集合标签和管理预览都不是播放令牌。

## 管理、恢复与审计

管理入口为 `/admin/music/featured/`，API 为 `/admin/api/music/featured`。GET 只返回当前编排、展示名和当前状态；PUT 一次原子替换三组位置，要求 `If-Match` 和 `Idempotency-Key`。曲目/集合状态、发布指针、策略、推荐版本和 catalogVersion 都在 D1 primary 条件事务中重查；失败时位置、目录版本、审计和回执一起回滚。

每次成功保存写一笔 `music.featured.update` 审计，只记录目标 ID、顺序和修改说明。不记录媒体字节、object key、Cookie、Access token 或会员资格。

管理页支持拖动和上移/下移键盘替代。编辑状态保存在按管理员隔离的 `station-music-featured:v1:{actor}` sessionStorage，仅含目标 ID/显示文本、本地顺序、版本、修改说明和待确认原操作。结果未知时不创建新写入；使用原内容、原版本和原键核对。明确 409 冲突保留本地编排，运营可读取新版本号后再次核对和保存；不会静默覆盖服务器变更。

## 迁移与运维边界

0008 只追加 `music_featured_home` 和 `music_featured_items`，不改旧曲目、集合、会员、付费、媒体或审计行。缺表时 readiness 失败关闭，不运行时建表或降级成未限制推荐。

本包不执行部署、远程 D1 迁移、预发白名单、开关或配额变更。后续预发必须保持 public 关闭，先备份并按顺序通过 Wrangler 正式流程应用尚未远程应用的 0006、0007、0008，再部署包含新静态资源和 Worker 的同一版本，最后在 Access 内验证管理 GET/PUT 和公开投影。新后台页、拆分 bundle 和样式的精确白名单留给该预发任务生成与审查，不在本包中扩展入口。

回退 Worker 不能撤销 D1 schema。回退前必须关闭 public 并停止推荐管理写入；旧 Worker 不读新表，但也不会清理新配置。恢复包含 0008 合同的版本后再单独开放。

当前本地验证不等于真实 Access、真实曲目、iPhone Safari、微信/X 或生产验收。这些统一留到 M6；本地截图、执行明细和 session 材料不附在 PR 中。
