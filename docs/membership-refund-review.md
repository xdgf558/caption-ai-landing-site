# VIP 退款人工审核

2026-09-09：用户确认采用人工审核。基线为已上线的 main@109b3d9（PR #118）。本轮仅实现与测试，不执行生产迁移、部署、真实退款或会员撤销，不进入音乐阶段。

## 审核范围

- 后台工作台增加「VIP 退款审核」入口：`/admin/membership-refunds/`。API 为 `/admin/api/readers/membership-refund-reviews`。
- 待审核队列直接来自 `reader_credit_ledger` 的 `creem-credit-pack` 冲正行。包含历史退款/拒付；同一冲正只有一份最终决定，不依赖再次收到 webhook，也不自动补写生产记录。
- 不改变 Creem 回调、现金退款、积分冲正规则。收到退款或出现负积分都不会自动撤销 VIP。
- 审核结果只有「确认无需撤销 VIP」与「撤销所选兑换的未使用期限」。未确认关联时不提交，继续留在待审核；提交必须写明至少 10 字依据并确认审核编号。
- 可选兑换必须属于同一账户，有 PR #118 原始回执，且流水顺序处于同源充值之后、冲正之前。此窗口只筛候选，不证明资金来源；资金关联仍须人工核对。
- 所选兑换的原始积分合计不得超过本笔已冲正积分。零积分冲正无可撤销额度。不支持任意输入新到期日或任意扣除天数。
- 只有旧 `membership_redeem` 流水、没有 0036 回执的历史兑换不能在本工具撤销。已用完、未知会员来源、未来开始日、异常日期或无法验证的续期链也不能撤销；不得据此误称历史问题已全部处理。

## 期限计算

会员资格唯一来源仍是 `reader_memberships`；新增表保存审核依据和操作结果，不用于授予 VIP。

以当前到期日向前计算连续的已知兑换区间。每次原始期限长度由回执的「原到期 / 兑换时间 / 新到期」计算，不使用固定 30 天代替 SQL 日历月。既往人工撤销量纳入计算，校验相邻回执及当前会员行是否能对应；超过 200 条历史时失败关闭，不截断后猜测。

撤销所选区间在提交时尚未使用的完整部分，精度为秒，向下取整。后续兑换的剩余时长保持不变并向前衔接，不能直接恢复旧到期日而误删后续续费。已经消费的时间不会追溯扣除。页面显示预计值，实际提交只会撤销当时仍未使用的部分。

同一兑换最多被人工撤销一次；同一冲正审核决定不可覆盖。一个退款涉及多次兑换时，应一次选齐已明确关联的兑换。部分退款不足以覆盖某次兑换原价时，不允许本工具自动按比例撤销，继续人工核对；没有引入 FIFO 资金归因。

## 并发与审计

- GET 返回包含原会员、冲正、充值、兑换及已有审核记录的版本摘要。POST 必须带该版本；期间续费、会员变更或其他审核会返回 409，要求重读。
- 最终会员行、所有选择项、审核结果、管理员审计日志在同一个 D1 batch 中提交。操作 token 限制每项写入；审计/选择项/最终期限的 NOT NULL guard 将零命中不一致变成事务失败并回滚。
- 冲正 ID 为唯一审核键。同一管理员、同一版本、同一决定、理由和选择项的重试返回原结果，不再次缩短期限。未知响应后客户端锁定表单，只允许重载核对，不自动换版本重试。
- 管理员身份从已验证的 Access JWT 取得，不能由前端或邮件请求头指定。所有路径经过现有全局 Admin gate；POST 额外验证同源 Origin、12KB 请求体上限；响应 no-store，不返回 SQL 错误。
- 不改变积分余额、积分流水、原始兑换回执、小说单项权益或游戏权益。原兑换同键重放仍保留原操作回执，当前会员摘要反映最新期限。
