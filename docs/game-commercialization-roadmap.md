# 游戏商业化任务清单

更新时间：2026-09-05。网站方向：免费游戏吸引玩家，可选付费内容获得收入；先验证《打工养猫日记》，再接入新游戏。

SnapCopy 和猫栈拼音继续免费提供，保留正常展示、下载和基础收录，不纳入本轮主动推广。

## 执行顺序

| 任务 | 范围与交付物 | 验收条件 | 当前状态 |
| --- | --- | --- | --- |
| 1. 首款游戏付费内容上线准备盘点 | 核对首批商品、实际效果、预览、种子价格、兑换/冲正实现与测试；记录生产证据缺口，给出上架候选清单 | 有可审查的商品交付边界、测试结果和上线门槛，不把模拟测试当生产验收 | 盘点完成，待 PR 审查；不是上线批准。见 [任务一报告](cat-life-paid-launch-readiness.md) |
| 2. 补齐缺口并验证付费意愿 | 先处理任务一的售前展示和测试缺口，再逐商品白名单验收、小范围观察，批准后开放销售；建立游玩、回访、商品查看、兑换与真实充值的统计 | 两个商品分别完成验收；无异常扣点/授权；测试赠送积分与真实充值区分统计 | 未开始；生产操作需另行批准 |
| 3. 游戏 SEO 与获客 | 选择一种主语言，完善游戏介绍、真实截图、玩法和相关攻略，建立 Search Console 与试玩入口转化基线 | 搜索访问能连接到真实试玩数据，内容不承诺未上线商品 | 未开始；以任务二可用内容为推广边界 |
| 4. 新游戏接入与复用 | 沿用会员、积分、订单与后台；逐游戏隔离存档、商品、权益、版本和灰度开关 | 两款游戏间存档/权益不串用，重复提交/并发/撤销测试通过 | 未开始；不预先重写平台 |

任务一是盘点与上线准备方案，不包含生产激活、充值、扣点、冲正或部署。发现缺口不等于任务一未完成，但缺口关闭前不能把商品标记为可公开销售。每次推进应更新本表和对应验收证据，不能因为代码合并就把整阶段标为完成。

## 平台规则

- Station 积分全站共用；权益默认只属于商品标明的游戏，不自动跨游戏通用。
- 游戏金币、彩票、数值和本地存档不能兑换积分或官方权益；价格、扣点、授权和冲正由服务器决定。
- 首批只销售明确、一次性、账号绑定的外观内容。不增加随机付费奖励、数值优势或强制付费门槛。
- 后续跨游戏套装须另立商品契约，明确包含内容；不复用或重命名已有商品/权益 ID。
- 每次游戏内容更新同步更新游戏内版本说明。仅修改内部计划文档不升级游戏版本。
- 合并 PR 不等于部署；部署不等于开卖。保持商品生命周期和 rollout 双重门槛。

## 测量边界

任务二先确定事件口径与必要的隐私披露，再实施统计，不在本次盘点中新增追踪脚本。

- 获客：介绍页访问、点击试玩、成功进入游戏，避免把按钮点击当成成功游玩。
- 留存：按约定的去重与回访窗口统计，不将测试账号计入真实玩家结果。
- 商务：商品查看、确认兑换、服务端成功购买、冲正；客户端成功提示不能替代订单与账本。
- 收入：真实充值、支付退款和支付费用分别核对；积分消费另列，不能与充值重复计算收入。
- 测试赠送积分兑换只能证明交易链路，不能证明付费意愿。尚未取得数据时不设置虚构的转化率或收入承诺。
