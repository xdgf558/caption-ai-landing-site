### 四项硬规格

| 项目 | 不可省略的实现目标 | 主文档 |
|---|---|---|
| 媒体身份 | VIP GET/HEAD/Range 同时验证 grant 与独立移动会话 Bearer；accountId、sessionId 均相符。URL 单独转发、B 的 Bearer、同账号其他 session 都拒绝。本版不承诺抵御 URL 与原完整 Bearer 一同泄露。 | 8.4、9、12.4 |
| 到期暂停 | playbackValidUntil 是硬截止；超时、503、429 和刷新成功均不自动延长。到点先暂停、取消加载和清理受保护 PlayerItem，恢复验证后等待用户主动播放。revalidateAt 只是提前验证时间。 | 7、9.4、12.3 至 12.5 |
| 删除恢复 | 先生成并保存删除请求 ID 和只读 receipt，prepare 只提交其哈希；获得准备结果后用户明确 confirm。确认响应丢失或会话撤销后，以独立 DeletionReceipt 查询同一任务；重启不自动再次确认。 | 11、12.8、16.3 |
| 刷新恢复 | HTTP 发送前，将旧 refresh token、generation、固定 refreshRequestId 作为单个 Keychain envelope 持久化。重启重试原操作；成功后新 token 与清除 pending 原子切换。120 秒结果窗口结束后仍靠墓碑识别原操作，转重新认证且不误判为跨 ID 重放。 | 8.3、11、12.7 |

刷新验证至少覆盖四个崩溃断点：pending 已保存未发送；服务器已提交未返回；收到响应未保存；新状态已保存未发布。删除验证至少覆盖 prepare/confirm 响应丢失、Keychain 失败、登录会话撤销、账号行清理及状态查询失败。播放验证包含完整缓冲后到期持续 503/超时，以及实际媒体请求身份匹配。

主文档新增测试应连同原测试执行，不能仅修改文字期望。M0 可在本地/隔离环境运行 Mock 与最小模型，但输出必须标明证据层级；完整业务实现与集成测试分别在 M2/M3/M4 完成。缺少签名、真机或隔离后台时继续完成可执行部分，将相关验收保留为未通过。

### 操作与安全限制

- 不修改线上积分、支付、会员、内容发布和密码安全规则；不借机重构整个后台。
- 不使用全局 isVIP 放开音乐和小说；不把完整 VIP 文件下发游客后用前端截停。
- 不在旧的严格媒体 URL 上直接追加 token；不把实际 Bearer 放入 URL；不为 AirPlay 或拖动降级成匿名付费媒体。
- 不使用未文档化 AVPlayer header 参数作为发布依赖；不复制 Safari Cookie；不关闭 CSRF、TLS 或 Apple 验签。
- 不因 503 无限延长授权；不在删除确认后才首次保存查询秘密；不在刷新超时/重启后创建新 ID 重用旧 token。
- 不以模拟器、模型测试、静态检查或 Mock 成功代替真实后端/Keychain/实体 iPhone 验收。
- 不创建远端仓库、不自动提交/合并 PR、不部署生产、不运行生产迁移、不修改 Apple/Creem 配置、不进行真实购买或提交 App Store。

完成 M0 后报告：真实基线、可复用模块、四项方案的验证与阻碍、实际改动、执行的测试、未验证项、兼容性风险、是否需要有证据的规格变更，以及 M1 输入。不要直接进入 M1；有技术阻碍时也不要默默放宽认证和失败暂停要求。
