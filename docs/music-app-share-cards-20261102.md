# Station Cat Music: share links and cards

This change prepares public song and album share pages and their portrait previews for the iOS app. It does not deploy or enable them. The user selects the link sharing action; no accounts, credentials or campaign attribution are included.

- Paths are `/music/share/tracks/{canonical-slug}/` and `/music/share/albums/{published-album-slug}/`, with optional `?locale=zh-Hans|zh-Hant|en|ja`. The default locale is `zh-Hans`.
- The page returns Open Graph and X/Twitter tags and a visible fixed App Store link. The `card.png` child serves a pre-generated 1200 × 1500 preview from the current published work title, its published introduction, and its independently owned cover when available. Songs use a nonblank summary first, then the same published song's story if the summary is blank; if both are blank, no introduction is invented. Albums use their published description. Long introductions are visibly truncated with an ellipsis in the preview; the landing page and metadata use the complete introduction. The album `cover.png` child remains a publication-checked PNG thumbnail, preserving transparency and bounded to 512 pixels on the long edge and 2 MiB; no cover results in 404.
- No new player, third-party platform link, audio data, account information or fabricated description is exposed. Every request checks publication; the album route checks the published album and its independent cover. Responses use `private, no-store` and recheck after withdrawal, though third-party platforms may retain cached previews outside our control.
- `STATION_MUSIC_SHARE_ENABLED` must be explicitly set to the string `true`, and `STATION_CONTENT_PUBLIC_ENABLED` must already be enabled. Existing `MUSIC_DB`, `MUSIC_BUCKET`, `ASSETS`, and rate-limit secret must be available. No migration or flag change is added.
- Public `card.png` requests do not load a font or run the WASM renderer. The offline image key includes the template version, kind, slug, locale, title, artist, complete introduction and cover SHA-256. After live publication and cover checks, the handler reads only that exact key from `ASSETS`; a changed or withdrawn work cannot reuse its previous image. Missing cards fall back to the live verified cover (or the fixed App icon for a coverless work). Raw `/api/music/__share-card-files/` assets and their encoded aliases return 404 before static dispatch, including while the share feature is disabled.
- `node scripts/generate-station-music-share-cards.mjs snapshot.json output-root` prepares the release assets offline. The reviewed snapshot is an array of `{kind: 'tracks'|'albums', slug, locale, title, artist, description, cover: null|{path, sha256, contentType}}`; the cover path is a local original, and its hash must match the current server cover. Prepare all four locales from the exact published metadata projection. Copy the generated private asset directory into the preserved production asset set, with the matching Worker guard, then verify every current share image. A normal Astro build does not fetch or generate these cards. New or edited works use their safe cover fallback until the next card generation.
- The same HTML and metadata are sent to every user agent. A fixed inline script, authorized by its exact CSP hash, navigates a JavaScript-enabled browser to `https://apps.apple.com/app/id6822797145`; it accepts no caller-supplied destination. Crawlers can read the metadata without an HTTP redirect. A visible download link and `noscript` fallback remain available. A photo alone is not a clickable URL. Actual X and WeChat link-card behavior, cached previews, crop, and store opening must be tested on those platforms and cannot be guaranteed by this code.
- While general search indexing is disabled, the production `/robots.txt` response allows only `Twitterbot` to fetch `/music/share/` when both public content and sharing are enabled; the specific group explicitly disallows every other path. The wildcard group's full disallow remains intact. The indexing-enabled policy is unchanged. This is the dynamic `searchIndex.js` policy dispatched by the active route-migration profile, not the static `public/robots.txt` file. The dedicated content-rollback entry intercepts robots before delegation and remains fully closed regardless of incoming flags. A preserved-production overlay must export `stationRobotsResponse` and connect it to the existing dynamic robots path; it must not put this exception before a rollback wrapper.
- Before enabling, independently validate the current production Worker and assets, including the later L35 cover variants, and build from complete production content. A build using empty local novel folders is only a compile check and must never be deployed.
