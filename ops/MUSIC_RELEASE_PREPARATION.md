# M6-05 上线准备与分步批准

本文件是待执行的发布方案，不是生产就绪报告或部署授权。M6-04 仅按隔离预发范围核销；预算投递、备份读回、分层恢复和关闭演练的原始记录仍在仓库外。预发通过不代替生产绑定、真实会员、负载、内容和恢复验收。

## 当前交付范围

本切片整理生产资源方案、候选版本检查、监控/备份待决项和分步开放条件，不修改 `wrangler.toml`，不创建生产资源、安装 secret、执行远程迁移、部署或开放入口。生产资源创建、空库迁移、Worker 部署、真实内容发布、上传配额、导航和各业务开关分别记录批准范围。

## A. 独立生产资源：首个待批准操作

| 项目 | 拟执行内容 | 完成后核对 |
| --- | --- | --- |
| 音乐 D1 | 新建 `station-cat-music-production`，仅作为 MUSIC_DB | 新 ID 与原会员库、预发两库、恢复库均不同；新库没有业务数据 |
| 私有 R2 | 新建 `station-cat-music-production-private`，仅作为 MUSIC_BUCKET | r2.dev 禁用，无自定义公开域，无对象；不设置删除已完成媒体的生命周期 |
| 初始化 | 只向上述新空库依次应用已审 0001–0008 | 迁移回执与源码文件相符；外键、设置及关键触发器就绪；配额 0、charge 0、无曲目/会话/统计数据 |
| 身份 | 不新建生产音乐身份库，不复制预发账号 | 后续 Worker 沿用原会员库只读判断；原 WAITLIST_DB 不迁移、不恢复、不写测试会员 |

先只读确认目标名称未被占用。若同名资源已经存在，停止并核对 ID、归属、内容和用途，不自动接管、删除或重建。Cloudflare 返回 ID 后保存在私有运维配置中；检查目标为本轮批准的新资源，才允许迁移。

资源初始化配置只列批准的音乐 D1/R2、账号及绝对迁移路径，不含 WAITLIST_DB、原站桶、Worker 入口、assets、域名或调度。资源操作始终显式指定该配置和 MUSIC_DB；禁止裸运行 `d1 migrations apply`、改写已应用 SQL、手填回执或复制预发导出作为生产初始化。未获得单独部署批准前，不将新绑定写进实际生产部署配置。

执行前用已安装 Wrangler 的 `--help` 核对 `d1 create`、`r2 bucket create`、`d1 migrations list/apply` 等命令。任何创建返回不明确时先只读盘点，不能盲重试。失败的半成品保持隔离并登记，不把“没部署 Worker”写成“没产生云端资源”。

## B. 生成可审查的关闸发布候选

资源准备后，先钉住已审且 CI 通过的提交，再制作完整 Worker 与静态产物。比较**当前生产部署源码到候选源码**的全部差异，不只看最后一笔 PR；重点回归共享 Header/Footer、语言切换、会员回跳、Access、原站路由以及 scheduled/queue。

候选从完整原站配置派生；保留原 WAITLIST_DB、CONTENT_BUCKET、DOWNLOADS_BUCKET、AI、EMAIL、队列生产者/消费者、cron、支付变量及既有秘密名称。只增加已批准的 MUSIC_DB/MUSIC_BUCKET 与音乐配置。不得用预发裁剪 Worker 或八页 assets 覆盖正式站；不得把预发 Access AUD、身份库、Cookie 翻译或测试夹具带到生产。

初次候选必须显式关闭 public、uploads、vipDelivery、analytics、cleanup 五旗，并保持 `MUSIC_SHARE_CARDS_ENABLED=false`。首次没有统计数据时 `MUSIC_ANALYTICS_RETENTION_ENABLED=false`；后续若已有统计数据，停采集不能顺带停保留清理。独立生成生产限流 secret，通过秘密通道安装，不能复用预发值、出现在配置/argv/日志中；安装同样属于单独批准的生产操作。

保持所有音乐 HTML（含四语、别名、无尾斜杠及编码路径）在 assets 之前经过 Worker 总闸，关闭时不能由静态路由漏出曲库。目录、媒体、卡片、统计的总闸与失败封闭都要核对；管理 API 仍由原生产 Access 和 Origin/CSRF 保护。

若把配置移到 `.generated/` 或私有目录，必须重算 main、assets.directory 和各 migrations_dir 的相对路径，逐项比对解析后的资源与源路径。Wrangler dry-run 只能验证打包，不能证明远程绑定、私有桶、配额或权限就绪。compatibility_date/flags 的改动需单独解释和回归，不照搬预发值。[Wrangler 配置](https://developers.cloudflare.com/workers/wrangler/configuration/)

候选至少运行现有 CI：全量测试、音乐上传/后台合同、D1/R2 runtime、音乐独立预览、完整构建、预发闭包检查，以及原站/文章/支付/音乐后台浏览器测试。记录提交与构建身份；代码、配置或 assets 变更后，仅复用仍适用的旧结果。

## C. 开放前必须处置的验收缺口

| 范围 | 处置条件 |
| --- | --- |
| U01–U16 / I01–I26 | 将现有实现测试、CI、预发 HTTP 和设备反馈逐项映射；缺证据仍标待测，不能由“npm test 通过”整表勾选 |
| 资格与媒体 | 在当次候选核对匿名/普通/VIP/过期、登出/撤销、跨账号、HEAD/Range/304/缓存、下架与政策边界；不得在生产伪造 VIP 或触发真实支付来补测 |
| 设备与性能 | 500 曲、30 次首次有声、完整 30 分钟测量分别补齐；用户接受提前结束的循环测试不能换算为完整时长 |
| 系统中断 | 区分公开播放器与后台私有控件；既有 iPhone 反馈只覆盖当时明确操作，不自动覆盖所有蓝牙、系统切歌、设备和网络组合 |
| 限流与故障 | 保留偶发 503 及未知原因；在隔离预发观察故障分类、可信来源头、并发原子计次和恢复。跨区域负载测试须有来源、时长、请求上限及预算批准 |
| 完整恢复切换 | 分层恢复结果不是已部署恢复站点的 HTTP/Access/手机播放验收；真实恢复到新目标时按当次绑定、对象身份和会员现状重新核对 |

安全边界失败不接受为“已知限制”放行。性能/设备覆盖若不能补齐，必须给用户具体缺口、可开放规模和观察方案，取得对该限制的明确接受；不能只在最终清单写“通过/降级”而无依据。未处置完不建议正式开放。

## D. 监控与备份方案：待运营者定标

账号预算通知继续按运营者已确认的阈值和收件人管理，不等于音乐独立费用上限。原始账单、邮箱和运行数据不写进仓库。生产请求量和单位成本要在实际资源/候选上建立基线；CPU、D1 行读取写入、R2 操作不能由播放器页面耗时反推。[Workers 指标](https://developers.cloudflare.com/workers/observability/metrics-and-analytics/)

以下为小规模开放的建议，尚未建立自动监控或定时备份：

| 项目 | 建议响应/频率 | 开放前需确认 |
| --- | --- | --- |
| 权限/数据泄漏 | 任意一次即停公开交付并保留证据 | 执行关闸的人和备用联系人 |
| 非预期 5xx / 限流截止 | 停止连续请求并分类；持续故障关 public，不绕过限流/VIP | 生产基线、告警条件与通知渠道 |
| 429 | 尊重 Retry-After，不自动重试制造流量；核对来源/全局额度与请求模式 | 允许的试运行流量与阈值 |
| 存储/未决写入 | 沿用 80% 提醒、100% 拒绝上传；未决写入逐项跟进 | 初始业务配额、负责人；初始化仍为 0 |
| 首次开放观察 | 建议首小时有人值守，每 15 分钟检查，异常立即处理；后续检查频率按基线调整 | 值守窗口、负责人，不能由本文推定已排班 |
| 离机备份 | 建议有业务变更期间每日及每次迁移/发布维护前备份，30 天人工保留 | 生产数据上传到指定私有存储的范围、频率、负责人及可接受数据损失窗口 |
| 恢复目标 | 区分停止交付、恢复只读、恢复写入；用生产规模的隔离演练定标 | RPO/RTO 的目标和实测，当前不承诺具体 SLA |

建议“每日备份”不自动保证 RPO 24 小时：备份失败或无法取得一致快照时，恢复点会更旧。必须检查最近成功备份的新鲜度。D1 Time Travel 与离机 SQL/媒体备份分别记录；它不恢复 R2，也不能当作原会员/支付回滚授权。[Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

30 天到期提醒与人工确认删除沿用 [M6-04 运维合同](MUSIC_OPERATIONS_READY.md)；新增每份生产备份都需独立登记和到期处理，不能沿用预发单份备份的提醒当成持续任务。尚未获得生产备份上传授权时，不上传生产数据库或媒体。

## E. 分步上线与停止条件

1. **关闸部署**：用户批准具体提交、完整配置与 assets 后部署；音乐仍关闭，先验收原站和音乐关闭路径、后台 Access、diagnostics。生产与预发各保存版本及回退方案。
2. **内容准备**：用户批准正式作品范围和上传配额后才开放受控上传。预发授权不自动变成正式发布许可。来源材料可选，不伪造 approved；MP3、独立试听、技术核对和显式发布合同不变。操作后关闭上传。
3. **开放公开读 / VIP**：分别批准后启用并按当次资格验收。封面和歌词可匿名展示，完整音频仍每次 `/audio` 核对 VIP。公开总闸开启意味着知道链接的人可能访问，不能称为账号白名单灰度；需要白名单试运行时应先独立实现入口限制。
4. **导航 / 分享卡片 / 统计**：各自独立评审和批准；导航不是 API 门禁。统计必须满足隐私版本、明确同意、保留任务和健康条件；无统计开放也可继续播放。不顺手开启 cleanup。

发现严重故障先以兼容当前 schema 的候选关闭 public；保留账本、对象和审计。切旧 Worker 不恢复数据库或媒体，不能退到不识别音乐守卫的处理器。关闭后核对音乐页面/别名/API 的拒绝及原站业务不受误伤；只在原因修复并重新批准后恢复读取。

## 交付边界

仓库只存方案、实现、测试和阶段状态；实际账号、资源 ID、部署版本、HTTP/设备记录、备份链接和 session 不附 PR。资源准备完成也只能核销 A，不能把整个 M6-05 标 DONE。最终开放必须同时具备可追溯的候选、已处置缺口、运营负责人、恢复方案和用户批准。
