# M6-04 运维就绪与演练 runbook

本文件是执行合同，不是已完成验收报告。实际账号、版本、书签、响应、账单、备份、对象清单、身份与执行结果全部留在仓库外的私有目录。每项记录“已验证 / 待验证 / 不适用及依据”；缺项不能用 diagnostics 200 或本地构建通过代替。

## 1. 环境与候选版本

| 项目 | 就绪要求 |
| --- | --- |
| 预发 | 独立 Access 应用、音乐 D1、隔离身份 D1、私有 R2；生产 Cookie 无效 |
| 生产 | 重新核对线上 Worker 版本与配置，音乐 D1/R2 与 WAITLIST_DB、CONTENT_BUCKET、DOWNLOADS_BUCKET 均分离；不复制测试账号或预发曲目 |
| 身份 | 生产仅复用既有会员只读判断，不绑定预发身份库；预发不读写生产会员 |
| 包 | 钉住已合并源码，测试通过，同一构建的 Worker 与静态资源；预发只包含既定八页依赖闭包 |
| 开关 | 迁移/维护使用五闸全关配置；统计启用另有隐私和保留期条件 |
| 密钥 | 独立限流 secret 仅存云端秘密，配置、命令参数和输出均不含值 |

仓库的 `wrangler.toml` 不预填生产音乐资源，不修改原站队列、cron、支付或邮件配置。按运营者的范围决定，M6-04 验收目标为隔离预发；生产音乐资源创建、绑定、初始配额和生产部署前检查移至 M6-05，仍须分别批准，不能从预发通过推导生产就绪。

先运行 `npm run build:music:staging-assets` 和 `npm run build:music:staging-maintenance-config`。生成器及运维 helper 共用隔离校验：精确检查账号、入口、域名、Access、两库、桶、静态目录/Worker 优先、迁移目录与日志设置；拒绝额外 env、build、cron、queue、绑定和明文 secret。五个旗均需存在且为字符串 true/false，输出全部为 false。将来确需扩展预发配置，先独立审查守卫与测试，不临时绕过检查。

该检查只验证本机受版本管理的源配置，不能证明远程配置一致，也不会部署。必须重新生成文件并逐项比较；手改 `.generated` 后不得沿用之前的通过结论。

## 2. 只读检查顺序

所有命令先用已安装 Wrangler 的 `--help` 核对，指定配置文件，日志路径设在仓库外。若认证失败，停在失败处；不借用生产凭据、临时取消 Access 或把 token 填进 URL。

1. `wrangler deployments list --config ops/music-staging-app.jsonc --json`，选择当前部署所引用的版本，再 `wrangler versions view <已核对的版本ID> --config ops/music-staging-app.jsonc --json`。生产只读检查使用 `wrangler.toml`，分别保存，不能混用。
2. 对已批准的音乐桶分别运行 `r2 bucket dev-url get`、`r2 bucket domain list`、`r2 bucket lifecycle list`。r2.dev 必须禁用；无自定义公开域。已完成对象不得被独立生命周期策略删除；默认未完成分片清理不等于应用对象清理。
3. 对两个预发绑定运行 `d1 info`、`d1 time-travel info` 及 `d1 migrations list --remote`，记录真实版本、可用书签和未应用迁移。不能依据本地迁移目录断言云端已应用，也不手填回执。
4. 已认证 diagnostics 核对旗、quota/charge、schema、限流、cleanup；匿名访问必须进 Access。HTTP 状态与 JSON 组件状态分开记录。unresolvedWriters/retainedBytes 必须有跟进人，不能手删会话或停用证明释放容量。
5. 记录公开目录/试听/完整音频的 200、206、401/403、429、503 分布与时延，先分类再处理。一次成功不能抹去此前故障。`music_rate_limit_failure` 只取固定 category/stage/reason，完整 tail、请求路径和 Ray ID 不公开。

R2 公开入口的两种方式见 [官方说明](https://developers.cloudflare.com/r2/buckets/public-buckets/)，命令见 [Wrangler R2](https://developers.cloudflare.com/workers/wrangler/commands/r2/)。

## 3. 预算、容量与告警

美元预算、负责人、收件邮箱与通知可用性均需运营者确认，不用猜测值创建告警。Cloudflare 的 Budget Alert 按账号当前账期的累计用量费用触发，包含原站等其他产品；不能称为“音乐单独账单”。它只提醒，不停止消费，不是硬性限额。按产品的用量通知另核对 Workers、D1、R2 可用指标。设置后检查实际阈值和收件人，并验证通知投递；仅保存页面不算投递验收。[Budget alerts](https://developers.cloudflare.com/billing/manage/budget-alerts/)

音乐存储上限在 MUSIC_DB 设置，按既有 charge 视图计入成功对象和未释放预留。达到 80% 提醒、100% 拒绝新上传；播放不因上传满额自动停用。不把本机样本容量作为生产容量，不自动提升配额、删除对象或扩大公开 JSON 正缓存。

按实际请求和账号账单估算增量：Worker 请求/CPU、D1 读取/写入、R2 存储/操作、日志及备份。一次播放可能发起多次 Range/HEAD；固定分钟限流不是月度费用封顶。关 public 能停止后续音乐业务读取，但不能追回在途响应或免除已消耗账单。

运营检查至少涵盖：5xx/限流超时、429 比例、Worker CPU/错误、D1 时延/行读取写入、R2 操作/容量、上传 charge 与未决写入、备份新鲜度、Access 失败和统计清理健康。各自阈值应由预发流量基线与预算定标，未定标不得标“告警就绪”。首次上线期间由指定操作员保持可联系并人工检查，不能将本文当成已创建 cron/监控服务。

隔离预发采用有操作员在场的人工检查：非预期 5xx/限流超时立即停止后续验收并分类，不能自动重试掩盖故障；429 核对 Retry-After 后停止本轮请求；未决写入大于零即列逐项跟进；容量沿用 80%/100% 边界。预算通知投递验收只覆盖预算通知。生产请求量、CPU、D1/R2 用量阈值与持续监控的负责人/频率必须在 M6-05 开放前定标，不能把预发人工检查称为全天候监控。analytics 关闭且无统计数据时，统计清理检查可记录不适用及依据。

## 4. 一致备份与恢复演练

恢复包包含：音乐 D1 导出、当前配置/源码与迁移清单、登记对象的私有备份及 id/key/size/hash/用途/派生关系映射。预发身份库单独备份；生产身份/交易备份按原系统制度处理，音乐恢复不得把全站会员或支付回滚到过去。

导出前安排维护窗口，停用上传/清理/统计写入并暂停后台编辑、发布和人工 SQL；盘点在途 PUT，未确认写入不能因一次空 HEAD 就认作没有对象。关 public/VIP 只阻断音乐交付，不会锁住后台所有写操作。不能仅看五旗关闭便声称拿到了跨服务原子快照。

D1 使用 `d1 export <已核对绑定> --remote --config <对应配置> --output <私有文件>`，本地恢复检查 integrity_check 与 foreign_key_check。对照导出库下载已登记对象，逐项验证实际字节数和 SHA-256，并检查完整/独立试听与修订引用。另做桶对象清单对账，未登记对象列待办；禁止仅备份目录中的已发布曲目。数据库完整性通过不证明媒体可恢复；只有登记对象核对也不证明桶中没有孤儿对象。

恢复导入不能只以 SQLite 能执行导出文件作为依据。音乐表存在循环外键：先创建全部被引用表，再在同一 D1 事务内导入相互引用的数据，完整安装导出中的索引、视图与业务触发器后验收。需要延迟外键时使用 `PRAGMA defer_foreign_keys=ON`，它不取消事务结束时的校验；不得删除外键或业务触发器来放行。若文件导入失败，先确认独立目标是否仍为空，再决定恢复路径；不直接重跑到已有数据的库。通过远程绑定执行原子 `batch` 时，只绑定已核对的恢复资源，不部署公共测试路由。[D1 导入说明](https://developers.cloudflare.com/d1/best-practices/import-export-data/) · [外键与事务](https://developers.cloudflare.com/d1/sql-api/foreign-keys/)

处理导出 SQL 必须用 SQLite 解析完整语句，不能按分号切触发器。保留原始备份，规范化后的导入文件另存私有目录；不得改资产字段、伪造迁移回执或丢弃会计数据。遇到内部序列表，先核对每个自增表的历史高水位；不能假定现存最大 ID 就等于历史最大 ID。无法等价恢复时停止。导入后从云端重新导出，逐表逐字段比较，并比较索引、视图、触发器定义及迁移回执；身份库只允许事先明确的测试会话吊销差异。`integrity_check` 在 SQLite 副本执行，D1 侧另外检查外键，不把本机结果写成远程执行了同名 PRAGMA。

Time Travel 只恢复 D1，不恢复 R2。其窗口取决于账号方案（官方列 Paid 30 天 / Free 7 天）；记录实际适用窗口，不能一律承诺 30 天。`time-travel restore` 会覆盖原库、取消在途查询，应记录恢复前后书签并单独批准，不能拿活跃业务库做试验。[Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

完整云端演练应使用单独批准的空恢复库、私有恢复桶和不接生产的受控环境，导入导出包后核对 D1 外键、对象哈希、发布投影、独立试听、无会员拒绝 full 与过期卸源。恢复后的预发测试会话应吊销或换新；恢复不能复活已撤销会员、已退休写入者或已释放 charge。生产会员永远以当前原会员库为准。

恢复旧对象可能改变 ETag/版本身份，不能只复制到原 key 后就开放。保持新写入关闭，在隔离恢复环境核对对象身份、条件读取和退休状态；需要修复身份引用时单独审查，不手改不可变资产字段、删触发器或重用一次写入 key。测量真实 RPO/RTO，并安排可恢复的离机备份及保留/删除策略。本机导入成功不是云端灾备；本机哈希不是离机备份。

离机备份使用运营者指定账号的 Google Drive 私有目录，仅所有者可访问，禁止链接公开。上传后重新下载，比较整包及清单中每个文件的字节数和 SHA-256，再用读回数据校验恢复；上传完成提示不是恢复证明。备份包含私有数据库与媒体，排除 Access JWT、原始 Cookie、限流 secret 和执行日志。实际账号、目录/文件 ID、书签和哈希仅保存在私有记录中。

保留期为 30 天，从备份上传完成计算；每份备份登记到期日并安排到期提醒，由操作员确认删除该份到期文件，核对最终结果。该流程是人工保留策略，不是 Drive 自动生命周期或精确到秒的删除保证；提醒失败、离线或未确认时仍属待清理，不能记作已删除。不得清空整个文件夹或以清理备份为名删除在线数据库/对象；后续备份须各自登记期限。定期备份频率、生产 RPO/RTO 目标与持续调度在 M6-05 上线前落实。

演练分别记录备份覆盖时点、关闭确认、恢复操作开始和验证结束，保留失败尝试与重试耗时。维护期两次完整导出与对象清单相等，只证明该窗口未观察到变化；云端资源恢复、通过远程绑定调用处理器、本地 workerd 恢复、真实 HTTP/Access 与真机播放应分别记结论，不合写成完整云端播放灾备。测得的预发耗时不能作为生产恢复 SLA。临时恢复资源在证据和离机副本验证后按精确资源清单清理，并核对没有误删实际预发资源。

## 5. 关闭、回退与恢复读取

- 限流/VIP/数据库故障：关闭 public，保留拒绝行为；不跳过计次、扩大匿名权限或改成公开桶。
- 上传或清理异常：关闭对应开关，保留 charge、对象和审计，逐项恢复；不做整批删除。
- 统计异常：关闭 analytics 采集；若已存在统计数据，仍按既有保留合同运行清理直到到期，不随意关 retention。

预发关闭演练：保存当前部署配置与版本 → 重新生成五旗全关维护配置 → dry-run → 部署该维护配置 → 验证已认证目录/音频返回 MUSIC_PUBLIC_DISABLED、未增加 D1 限流计数，匿名仍进入 Access。R2 零读取要区分已部署源码的提前拒绝路径、本地计数断言和真实云端遥测；没有云端逐请求指标时，不把前两者写成实测云端零读取。然后只在演练授权范围内恢复此前的 public/VIP 状态；upload/analytics/cleanup 不顺手开启。每次都有独立验证结果，失败留在关闭状态。

回退候选必须保留逐次 VIP、限流失败封闭、当前 schema 与资源身份协议。禁止直接 `rollback` 到早于音乐守卫的版本；旧代码可能不认识 MUSIC_PUBLIC_ENABLED。若只能使用不兼容的旧版，应先在不会随 Worker 回退失效的入口阻断音乐页面、别名和 API，独立验证阻断后再处理。不能直接阻断全站支付、小说或其他产品来代替音乐方案。

回退 Worker 不回退 D1，也不能恢复已删除的 R2 对象。恢复读取前重新检查：新鲜身份/下架状态、权限/试听、限流与配额；账号或支付回退、正式内容发布、生产部署和导航开闸属于独立授权。

## 6. 交付与退出

M6-04 只有在目标环境的绑定/私有桶、预算通知、容量、备份与恢复、关闭和恢复读取均有实际结果，且未验证项明确处置后才标完成。脚本/文档通过只算本地准备完成。

未确认的通知阈值/收件人、离机备份去向及保留期、恢复环境与窗口必须列具体待办，不伪造运营决策。M6-04 的隔离预发验收完成后，M6-05 仍须准备独立生产音乐资源、绑定/私有桶/迁移/配额、生产监控与备份目标，汇总未完成的负载和设备覆盖，并取得正式内容与开放批准。仓库只更新状态、实现和执行合同，不附本地或云端执行记录；进入 M6-05 不等于已开闸或生产灾备通过。
