# snapCopy V1.4 開発ログ：写真理解の土台を整える

今回の V1.4 では、目立つ新しいボタンを先に増やしませんでした。

開いた瞬間に「大きな機能が増えた」と分かるようなバージョンではありません。

より正確に言うと、このバージョンでは snapCopy の大事な土台を整えています。

**写真理解**です。

snapCopy がやりたいことはシンプルです。写真を選ぶと、共有しやすい文案を作る。

でも、本当の最初の一歩は「書くこと」ではありません。

最初に必要なのは：

**この写真をちゃんと理解できているか。**

コーヒーの写真を、ただの机の写真として扱ってはいけない。
散歩中の街並みに、朝ごはんの文案を書いてはいけない。
猫の写真に、強すぎるテンプレート文をかぶせてもよくない。

だから V1.4 は、少し地味なバージョンです。

シーン認識の学習と評価に使う最初の画像セットを整理しました。

## v1 学習画像 260 枚を整理

snapCopy には、最初の v1 画像セットがありました。合計 260 枚です。

カテゴリは 13 種類あります。

朝食、カフェ、散歩、街、旅行、ペット、服装、フィットネス、夕焼け、家、仕事机、食べ物、そして分類しにくい unknown。

どれもかなり日常的なカテゴリです。

それが大事です。snapCopy が実際に見る写真も、こういう日常の写真だからです。

ただし、データセットには小さいけれど大きな問題があります。

**間違った画像が混ざると、モデルも間違ったものを学びます。**

プロンプトのスクリーンショットを朝食として学習してはいけない。
犬の写真が walking に入ったままではよくない。
旅行より街並みに近い写真は street に直した方がよい。
生成ツールの説明カードは、現実の写真サンプルではありません。

こういうものを残したままにすると、モデルは賢くなるのではなく、迷いやすくなります。

なので今回は、まず初回の手動整理を行いました。

## 整理結果

初回整理の結果はこうです。

- 元の 260 枚は削除せず、上書きもしない。
- 249 枚を今後の学習用として保持。
- 11 枚を clean データセットから除外。主にプロンプト画面やデータカード系の画像。
- いくつかのラベル違いを修正。
- 暗い写真、圧縮が強い写真、少しぼけた写真は、現実のユーザー写真に近いものとして残し、quality tag を付けた。

この方針はわりと気に入っています。

snapCopy は、完璧な写真だけのためのアプリではありません。

現実の写真は、少し暗かったり、少しぼけていたり、少し普通だったりします。
朝食はいつもメニュー写真のようには見えません。
机はいつも片付いているわけではありません。
猫も毎回きれいに構図へ入ってくれません。

モデルがきれいな見本写真だけを見ていると、実際の写真に弱くなります。

だから今回の整理は、データセットを「きれいな写真集」にするためではありません。

もっと大事なのは：

**信頼できて、追跡できて、これから育てられるデータセットにすること。**

## データセットの流れも整えた

V1.4 では、データセットまわりの運用も少し整理しました。

今は次のものがあります。

- v1 raw manifest
- v1 clean manifest
- クラス別 contact sheet
- cleaning report
- 学習可能な v1_clean ディレクトリ
- v2 データセット拡張計画
- Create ML トレーニングガイド
- モデル評価テンプレート
- App 側 Core ML 接続メモ

これらは、見た目には App の機能ではありません。

でも、小さな AI ツールにはとても大事です。

今後モデルが良くなったとき、それを「なんとなく良くなった」で終わらせたくありません。

このバージョンはどのデータを使ったのか。
どの画像を残したのか。
どの画像を外したのか。
どのラベルを直したのか。
なぜ暗い写真やぼけた写真を残したのか。
次のモデルは何と比べるのか。

こういう問いに答えられるようになって、写真理解は少しずつ土台を持ちはじめます。

## App 側にも準備を入れた

今回はフォルダを整理しただけではありません。

App 側にも、今後のローカルシーンモデルに向けた準備を入れました。

snapCopy には Core ML のカスタムシーン分類器を置ける場所があります。

今後、新しいシーンモデルを学習できたら、Apple Vision、OCR、ルールベースの判定と一緒に使えるようにします。

方向性はこうです。

Core ML モデルがある場合は、ローカルモデルを主な判断材料にする。
Vision ラベル、OCR、ユーザー修正は補助として使う。
モデルがまだ入っていない場合でも、現在の Vision rules と OCR に戻れる。
つまり、モデルが未完成でも App は壊れません。

写真理解診断画面も更新しました。

今後は Core ML Top-3 予測、最終 scene、confidence、手動選択の提案、ローカル評価状態、文案評価状態を見られるようにしています。

これは全ユーザー向けの機能というより、開発中の小さな明かりです。

文案が写真に合わないとき、あとから確認できます。

写真理解が間違っていたのか。
scene は合っていたけれど文案がずれたのか。
confidence が低く、手動選択を出すべきだったのか。

## なぜこれを開発ログに書くのか

外から見ると、V1.4 はあまり派手ではありません。

でも snapCopy にとって、この一歩はかなり大事です。

今後の文案が、テンプレートを貼っただけではなく、「写真を見て書いた」感じに近づけるかどうかに関わるからです。

コーヒーの写真は、ただのコーヒーではありません。

朝、机、暖かい光、一日が始まる前の静かな時間かもしれません。

猫の写真も、ただのペットではありません。

窓辺、低い光、だらんとした姿勢、たまたま撮れた一秒かもしれません。

写真理解がこういう細部を少しでも拾えるようになると、文案も画面に近づきやすくなります。

V1.4 は、そのための準備です。

## 次にやること

次は、整理した v1_clean データセットを使って、新しいシーン分類モデルを一度訓練してみます。

最初から複雑なモデルを目指すつもりはありません。

まず見たいのは：

日常シーンを安定して分けられるか。
どのカテゴリが混ざりやすいか。
整理後のデータで評価が安定するか。
暗い写真、圧縮写真、ぼけた写真が実運用に役立つか。
App に接続したとき、文案が写真に近づくか。

結果がよければ、v2 データセットへ広げていきます。

v2 ではもっと多くの写真、もっと多くの境界ケース、もっと厳しい評価が必要になります。

でも今は、最初の土台ができました。

派手ではありません。

引き出しを整理しているような作業です。

でも、毎日使う小さな道具を信頼できるものにするには、こういう目立たない場所から始まることが多いです。

snapCopy は少しずつ育てていきます。

まず写真を理解する。
次に、写真に近い文案を書く。
そして、共有しようか迷っていた小さな瞬間を、少し軽く外へ出せるようにする。
