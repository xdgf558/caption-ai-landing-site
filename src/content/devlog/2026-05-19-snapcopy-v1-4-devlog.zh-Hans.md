# snapCopy V1.4 开发日志：先把照片理解的地基整理好

这次 V1.4，我没有先去加一个很亮眼的新按钮。

它不是那种一打开就能立刻看到“哇，多了一个大功能”的版本。

更准确地说，这一版是在整理 snapCopy 后面很重要的一块地基：

**照片理解。**

snapCopy 想做的事情很简单：你拍一张照片，它帮你生成更适合分享的文案。

但这件事真正做起来，第一步其实不是“会写文案”。

第一步是：

**它到底有没有看懂这张照片。**

如果照片是咖啡，它不能只当成一张普通桌面图。
如果照片是散步路上的街景，它不能硬写成早餐。
如果照片里是一只猫，它也不应该用很夸张、很模板化的句子把画面盖掉。

所以 V1.4 做的事比较朴素：

先把用来训练和验证场景识别的第一批图片整理干净。

## 这一版先清理了 260 张 v1 训练图

之前 snapCopy 已经有一批 v1 图片数据，总共 260 张。

它们按 13 类日常场景分好：

早餐、咖啡、散步、街景、旅行、宠物、穿搭、健身、日落、居家、工作桌面、食物，以及一些暂时难以归类的图片。

这些类别很日常，也很像 snapCopy 会遇到的真实照片。

但数据集这件事有一个很容易被忽略的问题：

**只要里面混进一些错的图片，模型后面就会学歪。**

比如把提示词截图当成早餐照片。
比如把一张狗图留在散步类别里。
比如一张更像普通街景的旅行照片，还放在 travel 里。
比如一些不是照片本体，而是生成工具留下来的说明卡片。

这些东西如果不清掉，后面模型不是变聪明，而是会变得很困惑。

所以这次先做了一轮人工清洗。

## 清洗结果

第一轮清理后，结果是：

- 原始 260 张图没有删除，也没有覆盖。
- 保留 249 张，作为后续可训练图片。
- 剔除 11 张，主要是不适合训练的提示词截图或数据卡片。
- 修正了几张错类图片。
- 低光、压缩、模糊这些真实使用中可能会遇到的困难样本，没有简单删掉，而是保留下来并标记原因。

我比较喜欢这个处理方式。

因为 snapCopy 不是只给完美照片用的。

真实生活里的照片经常有点暗、有点糊、有点普通。
早餐不一定像菜单照片。
桌面也不一定整理得很好。
猫更不会每次都配合构图。

如果模型只看过干净、漂亮、很像展示样片的图片，它到了真实使用时反而会不稳。

所以这次清洗不是把数据集变成“好看图片合集”。

它更像是把数据集变成：

**可以被信任、可以追踪、可以继续长大的版本。**

## 这次新增了清洗流程

V1.4 里，我也把数据集流程整理得更工程化一点。

现在有了：

- v1 raw 原始清单
- v1 clean 清洗清单
- 每个类别的接触表
- 清洗报告
- 可训练的 v1_clean 目录
- 之后扩充 v2 数据集的计划
- Create ML 训练指南
- 模型评估模板
- App 端 Core ML 接入说明

这些东西看起来不像 App 功能。

但对一个 AI 小工具来说，它们很重要。

因为后面每一次模型变好，都不应该只靠感觉。

它应该能回答：

这一版用了哪些数据？
哪些图片被保留？
哪些图片被剔除？
哪几张被改了标签？
为什么保留一些低光或模糊样本？
下一版模型准备用什么数据比较？

当这些问题能回答时，snapCopy 的照片理解才算开始有地基。

## App 端也做了预留

这次不是只整理文件夹。

App 里也为后续本地场景模型做了准备。

目前 snapCopy 已经保留了 Core ML 自定义场景分类器的位置。

后续如果训练出新的场景模型，它可以和现在的 Apple Vision、OCR、规则判断一起工作。

大概的方向是：

有 Core ML 模型时，以本地模型判断为主。
Vision 标签、OCR 和用户修正作为辅助。
如果没有模型，App 仍然能退回到现在的 Vision rules 和 OCR 流程。
也就是说，就算模型还没放进来，App 不会因此坏掉。

我也更新了照片理解诊断页，方便后面看模型表现：

Core ML Top-3 预测、最终场景、信心值、是否建议手动选场景、本地评估状态，以及文案评分状态。

这些不是给所有用户看的功能。

它更像是开发期的一盏小灯。

当文案生成不贴图时，我可以回头看：

到底是照片理解错了？
还是场景对了，但文案写偏了？
还是模型信心太低，应该让用户手动选一下？

## 为什么这一步值得写进开发日志

如果只从外面看，V1.4 好像没有那么热闹。

但对 snapCopy 来说，这一步很关键。

因为它决定了后面文案能不能更像“看着照片写出来的”，而不是套模板。

一张咖啡照片，不只是咖啡。

它可能是早晨、桌面、暖光、安静、开始一天之前的小空档。

一张猫的照片，也不只是宠物。

它可能是窗边、低光、懒洋洋、刚好被拍到的一秒钟。

如果照片理解能多抓住一点这些细节，文案才有机会更贴近画面。

V1.4 做的，就是让这件事以后可以更稳地发生。

## 接下来

下一步，我会用清洗后的 v1_clean 数据先训练一版新的场景分类模型。

这版模型不急着追求复杂。

我更想先看几件事：

它能不能稳定分出日常场景。
它在哪些类别容易混淆。
清洗后的数据，是否让测试结果更稳。
低光、压缩、模糊这类困难样本，是否会拖累或反而帮助真实表现。
模型接进 App 后，是否真的能让文案更贴近照片。

如果结果不错，再往 v2 数据集扩充。

v2 会需要更多照片、更多边界案例，也会需要更严格的评估。

但至少现在，第一块地基已经开始铺好了。

它不华丽。

甚至有点像在整理抽屉。

可是一个日常工具要变得可靠，很多时候就是从这些不太显眼的地方开始的。

snapCopy 会继续慢慢长。

先看懂照片。
再写出更贴近照片的句子。
最后，帮人把那些原本差点懒得分享的小瞬间，更轻一点地发出去。
