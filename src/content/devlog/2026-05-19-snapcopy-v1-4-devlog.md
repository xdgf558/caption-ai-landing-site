# snapCopy V1.4 開發日誌：先把照片理解的地基整理好

這次 V1.4，我沒有先去加一個很亮眼的新按鈕。

它不是那種一打開就能立刻看到「哇，多了一個大功能」的版本。

更準確地說，這一版是在整理 snapCopy 後面很重要的一塊地基：

**照片理解。**

snapCopy 想做的事情很簡單：你拍一張照片，它幫你生成更適合分享的文案。

但這件事真正做起來，第一步其實不是「會寫文案」。

第一步是：

**它到底有沒有看懂這張照片。**

如果照片是咖啡，它不能只當成一張普通桌面圖。
如果照片是散步路上的街景，它不能硬寫成早餐。
如果照片裡是一隻貓，它也不應該用很誇張、很模板化的句子把畫面蓋掉。

所以 V1.4 做的事比較樸素：

先把用來訓練和驗證場景識別的第一批圖片整理乾淨。

## 這一版先清理了 260 張 v1 訓練圖

之前 snapCopy 已經有一批 v1 圖片資料，總共 260 張。

它們按 13 類日常場景分好：

早餐、咖啡、散步、街景、旅行、寵物、穿搭、健身、日落、居家、工作桌面、食物，以及一些暫時難以歸類的圖片。

這些類別很日常，也很像 snapCopy 會遇到的真實照片。

但資料集這件事有一個很容易被忽略的問題：

**只要裡面混進一些錯的圖片，模型後面就會學歪。**

比如把提示詞截圖當成早餐照片。
比如把一張狗圖留在散步類別裡。
比如一張更像普通街景的旅行照片，還放在 travel 裡。
比如一些不是照片本體，而是生成工具留下來的說明卡片。

這些東西如果不清掉，後面模型不是變聰明，而是會變得很困惑。

所以這次先做了一輪人工清洗。

## 清洗結果

第一輪清理後，結果是：

- 原始 260 張圖沒有刪除，也沒有覆蓋。
- 保留 249 張，作為後續可訓練圖片。
- 剔除 11 張，主要是不適合訓練的提示詞截圖或資料卡片。
- 修正了幾張錯類圖片。
- 低光、壓縮、模糊這些真實使用中可能會遇到的困難樣本，沒有簡單刪掉，而是保留下來並標記原因。

我比較喜歡這個處理方式。

因為 snapCopy 不是只給完美照片用的。

真實生活裡的照片經常有點暗、有點糊、有點普通。
早餐不一定像菜單照片。
桌面也不一定整理得很好。
貓更不會每次都配合構圖。

如果模型只看過乾淨、漂亮、很像展示樣片的圖片，它到了真實使用時反而會不穩。

所以這次清洗不是把資料集變成「好看圖片合集」。

它更像是把資料集變成：

**可以被信任、可以追蹤、可以繼續長大的版本。**

## 這次新增了清洗流程

V1.4 裡，我也把資料集流程整理得更工程化一點。

現在有了：

- v1 raw 原始清單
- v1 clean 清洗清單
- 每個類別的接觸表
- 清洗報告
- 可訓練的 v1_clean 目錄
- 之後擴充 v2 資料集的計畫
- Create ML 訓練指南
- 模型評估模板
- App 端 Core ML 接入說明

這些東西看起來不像 App 功能。

但對一個 AI 小工具來說，它們很重要。

因為後面每一次模型變好，都不應該只靠感覺。

它應該能回答：

這一版用了哪些資料？
哪些圖片被保留？
哪些圖片被剔除？
哪幾張被改了標籤？
為什麼保留一些低光或模糊樣本？
下一版模型準備用什麼資料比較？

當這些問題能回答時，snapCopy 的照片理解才算開始有地基。

## App 端也做了預留

這次不是只整理資料夾。

App 裡也為後續本地場景模型做了準備。

目前 snapCopy 已經保留了 Core ML 自定義場景分類器的位置。

後續如果訓練出新的場景模型，它可以和現在的 Apple Vision、OCR、規則判斷一起工作。

大概的方向是：

有 Core ML 模型時，以本地模型判斷為主。
Vision 標籤、OCR 和使用者修正作為輔助。
如果沒有模型，App 仍然能退回到現在的 Vision rules 和 OCR 流程。
也就是說，就算模型還沒放進來，App 不會因此壞掉。

我也更新了照片理解診斷頁，讓後面測模型時可以看到更多線索：

Core ML Top-3 預測、最終場景、信心值、是否建議手動選場景、本地評估狀態，以及文案評分狀態。

這些不是給所有使用者看的功能。

它更像是開發期的一盞小燈。

當文案生成不貼圖時，我可以回頭看：

到底是照片理解錯了？
還是場景對了，但文案寫偏了？
還是模型信心太低，應該讓使用者手動選一下？

## 為什麼這一步值得寫進開發日誌

如果只從外面看，V1.4 好像沒有那麼熱鬧。

但對 snapCopy 來說，這一步很關鍵。

因為它決定了後面文案能不能更像「看著照片寫出來的」，而不是套模板。

一張咖啡照片，不只是咖啡。

它可能是早晨、桌面、暖光、安靜、開始一天之前的小空檔。

一張貓的照片，也不只是寵物。

它可能是窗邊、低光、懶洋洋、剛好被拍到的一秒鐘。

如果照片理解能多抓住一點這些細節，文案才有機會更貼近畫面。

V1.4 做的，就是讓這件事以後可以更穩地發生。

## 接下來

下一步，我會用清洗後的 v1_clean 資料先訓練一版新的場景分類模型。

這一版模型不會急著追求很複雜。

我更想先看幾件事：

它能不能穩定分出日常場景。
它在哪些類別容易混淆。
清洗後的資料，是否讓測試結果更穩。
低光、壓縮、模糊這類困難樣本，是否會拖累或反而幫助真實表現。
模型接進 App 後，是否真的能讓文案更貼近照片。

如果結果不錯，再往 v2 資料集擴充。

v2 會需要更多照片、更多邊界案例，也會需要更嚴格的評估。

但至少現在，第一塊地基已經開始鋪好了。

它不華麗。

甚至有點像在整理抽屜。

可是一個日常工具要變得可靠，很多時候就是從這些不太顯眼的地方開始的。

snapCopy 會繼續慢慢長。

先看懂照片。
再寫出更貼近照片的句子。
最後，幫人把那些原本差點懶得分享的小瞬間，更輕一點地發出去。
