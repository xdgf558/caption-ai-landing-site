# R1 隔离销户执行验证

本目录只操作测试脚本创建的临时 D1、合成账号。`schema.sql` 不在任何迁移目录，执行器未被 `src/`、Worker 路由、定时任务或 Wrangler 配置引用。它不是可部署的生产销户服务。

运行：`npm run test:mobile:lifecycle`。测试服务绑定随机 loopback 端口，拒绝所有 HTTP 执行请求及出站访问；测试通过临时 D1 binding 调用执行内核。D1 持久化目录在测试结束后删除。

## 已实现的个人数据阶段

必须同时指定 isolated / synthetic-r1，存在夹具来源标记、匹配已审查表结构及数据库写入屏障，并且任务已经显式确认、账号已经冻结。dry run 只返回各表数量和未完成类别，不返回邮箱、凭据或正文。

阶段为 credentials → private_data → comments → identity → verify → retention_policy_review。每次领取一个 30 秒租约；owner、version、stage 和未到期租约共同限制提交。每次只处理一张表、最多 200 行，清理和进度在同一 D1 batch 中提交。失败事务回滚；崩溃后可等租约到期重新领取。过期持有者不能再写入。尚无后台自动重试调度。

- 先清除刷新结果、刷新 token、播放授权、授权码和会话，再清除密码、TOTP、登录 token。
- 删除书签、原始阅读记录、云存档及备份、账号限流记录、音乐偏好、收藏墓碑、最近播放及幂等操作记录。
- 评论保留正文和审核状态，将作者设为 NULL，清除来源、元数据、网络标识和审核人等字段。网站三个评论读取查询使用 LEFT JOIN，匿名显示支持四语；未公开评论仍不会出现在公开列表。正文可能包含用户自行披露的信息，需要后续删除/举报处理，不能宣称已完全不可识别。
- 账号改为不可登录的技术记录；移除邮箱、用户名和显示名。财务关联 ID 仍在，属于假名化保留。原邮箱再次注册取得新 ID，不能继承旧权益。
- 余额和账务记录不改动、不退款、不清零。建立独立待处理财务案。隔离数据库屏障阻止冻结账号重新激活、重新保存私人数据或被迟到回调赋予可用余额/权益。
- 核对所有目标表残留、身份字段及财务案后记录 `personal_completed_at`。公共回执保持 attention_required / retention_policy_review，`completed_at` 始终 NULL。

## 明确未完成的边界

没有批准财务最小字段/保留年限、回执审计期限、支付平台和备份保留规则。waitlist、feedback、管理员审计和支付原始 JSON 的软关联不靠邮箱猜测删除。发布者 R2/内容库不属于普通读者资产，不随账号清理。因此本批不会报告整项销户 completed，也不会启用生产执行。

旧备份恢复可能重新带回账号和凭据。本地写入屏障只能保护当前隔离库，不能替代备份恢复后的独立删除清单重放。R2 配置及真实恢复演练前必须设计不随旧备份倒退的清理证据和阻断策略。

## 活跃账号的同步长期保留与无损压缩

现有协议中的 favorite tombstone 保存歌曲版本，幂等记录保存 ID、请求摘要和原回执。本批不删除这些防重放信息，继续保留到明确确认的销户清理，并保持现有每账号 100,000 条操作上限。历史记录仍为 90 天、最多 1,000 首；这些展示数据的保留规则不能用于删除防重放信息。

`compact-receipts.js` 是独立的合成夹具工具，每次最多转换 200 条回执，把冗长字段名替换为带 `r1` 版本标识的元组。ID、digest、created_at 不变，API 回应中的字段和值逐项不变。短回执不做膨胀转换。数据库更新比较旧内容，重复运行无副作用；旧 JSON 与新元组均能解码。未知格式返回可重试 503，不当成“从未执行过”重新写入。

产品代码只增加兼容读取，普通写入仍存旧 JSON；没有压缩调度或生产开关。`restoreFixtureReceipts` 可在隔离演练中分批还原旧 JSON。未来若启用真实压缩，回滚到不认识元组的旧 Worker 前必须先全量还原并校验，不能直接回退读取器。

实际 D1 验证：收藏/取消收藏/关闭历史回执压缩后，回执丢失的旧请求仍得到原结果，不再写入；墓碑保留使旧版本的新请求继续冲突；旧历史 epoch 继续拒绝；另一账号原样；还原后整行记录等于压缩前。

若以后要突破条数上限或最终淘汰活跃账号防重放记录，仍需独立审查 generation / 有限重放窗口协议：基线切换与压缩原子提交，旧 generation 拒绝写入，客户端保留限制性隐私意图并用新 ID 重建。该协议尚未实现，本批无损压缩不宣称解决无限增长或永久可写问题。

## 测试证据范围

实际 Miniflare D1：跨账号隔离、评论匿名与审核状态、财务原样保留、同邮箱新身份、迟到写入拒绝、过期租约和并发领取、事务故障回滚、持久化 workerd 重启、200 行上限、未知表/缺少屏障拒绝执行、真实 confirmDeletion 冻结原子性。不是生产数据库、支付回调端到端或备份恢复验收。
